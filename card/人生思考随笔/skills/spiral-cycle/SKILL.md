# 螺旋周期：通用迭代框架

基于心流闭环周期（Struggle-Release-Flow-Recovery）的四阶段螺旋模型，为任何长期项目提供周期性收束机制，防止偏离轨道，确保持续迭代上升。

## 核心原则

1. **螺旋非线性**：不是A→B→C的直线推进，而是周期性循环上升
2. **阶段不可跳过**：挣扎期是必要的，恢复期不是浪费
3. **通用适用性**：不绑定特定领域，可用于学习、工作、文档维护、技能提升等
4. **周期性调用**：在关键节点主动触发螺旋检查，收束发散状态

## 何时激活

- 项目推进一段时间感觉"发散"或"迷失方向"
- 需要评估当前状态并决定下一步行动
- 感到倦怠、失去动力或效率下降
- 完成一个里程碑后需要整合再出发
- 定期维护（如每周/每月的周期性收束）
- 遇到瓶颈，不确定是坚持还是调整策略

## 四阶段螺旋

```
        ┌──────────────────────────────────────┐
        │           Spiral Cycle                │
        │     每次循环 = 一次螺旋上升            │
        │                                      │
        │    Struggle ──────→ Release          │
        │    (挣扎期)         (释放期)          │
        │       ↑                ↓             │
        │       └────────────────┘             │
        │    Recovery ←────── Flow             │
        │    (恢复期)         (心流期)          │
        │                                      │
        └──────────────────────────────────────┘
```

### Phase 1: Struggle（挣扎期）

**特征**：挑战>技能，感到困难、焦虑、想放弃
**神经机制**：去甲肾上腺素↑、皮质醇↑
**作用**：建立认知负荷，为后续心流做准备

**识别信号**：
- 任务变得困难，进展缓慢
- 感到焦虑或自我怀疑
- 信息过载，难以整合

**应对策略**：
- 分解任务，降低单次挑战强度
- 设定清晰目标（SMART原则）
- 建立专注仪式（固定流程进入工作状态）
- 接受挣扎是必要的，不因困难而放弃

**常见陷阱**：
- 跳过挣扎期直接寻求舒适 → 无法进入真正心流
- 挣扎期过长导致burnout → 需要主动进入释放期

---

### Phase 2: Release（释放期）

**特征**：暂时抽离，思绪漫游，灵感闪现
**神经机制**：内啡肽↑、伽马波增强
**作用**：潜意识整合，突破思维定势

**识别信号**：
- 刻意努力无效，头脑卡壳
- 需要放松但还未疲惫
- 隐约感到有新想法在浮现

**应对策略**：
- 短暂休息（5-15分钟）
- 散步、冥想、切换无关任务
- 不主动思考原问题，让潜意识工作
- 准备纸笔随时捕捉闪现的灵感

**常见陷阱**：
- 跳过释放期强行推进 → 思维僵化，效率低下
- 释放期变成逃避 → 无限制延长休息时间

---

### Phase 3: Flow（心流期）

**特征**：挑战≈技能，专注忘时，行动自如
**神经机制**：多巴胺↑、血清素↑、大麻素↑
**作用**：高效产出，峰值表现

**识别信号**：
- 时间感消失，数小时如几分钟
- 行动-意识融合，不假思索地执行
- 感到愉悦、掌控感和创造力爆发

**应对策略**：
- 排除干扰（关闭通知、隔离环境）
- 保持专注，不要主动打断
- 利用即时反馈维持动力
- 记录心流触发条件，建立个人数据库

**常见陷阱**：
- 追求"永久心流" → 忽视恢复期导致崩溃
- 在心流期切换任务 → 打断深度工作状态

---

### Phase 4: Recovery（恢复期）

**特征**：能量消耗，身心需要修复
**神经机制**：神经递质回落，身体修复
**作用**：整合经验，为下一轮螺旋蓄能

**识别信号**：
- 感到疲惫、注意力涣散
- 心流状态自然消退
- 轻度满足感但精力下降

**应对策略**：
- 深度休息（睡眠、营养补充）
- 主动恢复（轻度运动、社交）而非被动娱乐（刷手机）
- 复盘记录：本次螺旋的关键数据
- 庆祝成就，强化正向反馈

**常见陷阱**：
- 忽视恢复期 → 下一轮螺旋质量下降
- 恢复期仅依赖睡眠 → 恢复效率低
- 未复盘 → 无法优化下一次螺旋

## 工作流：螺旋周期调用

### 1. 状态诊断

使用 `/spiral status` 诊断当前处于哪一阶段：

```
问题清单：
□ 当前任务是否感到困难/焦虑？ → 可能是 Struggle
□ 是否卡壳且努力无效？ → 需要 Release
□ 是否专注忘时、效率极高？ → 正在 Flow
□ 是否感到疲惫但满足？ → 需要 Recovery
```

### 2. 阶段引导

根据诊断结果，执行对应阶段策略：

```
if Struggle:
    → 应用"挣扎期应对策略"
    → 设定清晰子目标
    → 必要时进入 Release

if Release:
    → 应用"释放期应对策略"
    → 设置时间盒（如15分钟）
    → 准备捕获灵感

if Flow:
    → 应用"心流期应对策略"
    → 保持专注，排除干扰
    → 设置外部闹钟防止过度沉浸

if Recovery:
    → 应用"恢复期应对策略"
    → 深度休息
    → 复盘记录
    → 决定是否进入下一轮螺旋
```

### 3. 螺旋检查点

在关键节点触发 `/spiral checkpoint`：

| 触发时机 | 检查内容 | 决策 |
|---------|---------|------|
| 每日结束 | 今日螺旋状态 | 是否需要额外恢复 |
| 每周结束 | 本周螺旋次数 | 调整下周节奏 |
| 项目里程碑 | 本阶段螺旋质量 | 是否进入下一阶段 |
| 感到迷失 | 当前螺旋位置 | 回到哪一阶段修正 |
| 瓶颈期 | 螺旋是否卡住 | 是否需要外部介入 |

### 4. 螺旋记录

维护个人螺旋日志：

```yaml
spiral_log:
  - date: "2024-04-19"
    cycle_number: 12
    phases:
      struggle: { duration: "2h", challenge: "文档结构调整" }
      release: { duration: "30min", trigger: "散步" }
      flow: { duration: "3h", output: "完成skill重构" }
      recovery: { duration: "1d", method: "睡眠+复盘" }
    insights: "结构问题需要周期性收束，而非一次性解决"
    next_action: "应用spiral-cycle skill到其他项目"
```

## 应用场景

### 场景 A：文档维护（如 md-chain-integrity）

**螺旋模式**：
- **Struggle**：文档经过多次迭代，结构开始发散
- **Release**：暂时停止编辑，阅读整体结构
- **Flow**：快速重构，建立新的收束点
- **Recovery**：验证链接，记录腐化模式

**调用指令**：当文档链出现腐化迹象时，周期性调用 `/spiral checkpoint` 收束结构。

### 场景 B：技能学习

**螺旋模式**：
- **Struggle**：学习新概念，感到困难
- **Release**：暂停刻意学习，做相关实践
- **Flow**：在项目中应用，融会贯通
- **Recovery**：复盘理解盲区，记录心得

**调用指令**：每周日 `/spiral status` 检查学习螺旋位置，调整下周计划。

### 场景 C：创作工作

**螺旋模式**：
- **Struggle**：收集素材，构思框架，感到混乱
- **Release**：离开工作，等待灵感
- **Flow**：高效创作，一气呵成
- **Recovery**：休息，接受反馈，准备修改

**调用指令**：创作瓶颈时，主动触发 `/spiral release` 进入释放期。

### 场景 D：项目管理

**螺旋模式**：
- **Struggle**：项目推进困难，需求不清
- **Release**：团队讨论，头脑风暴
- **Flow**：高效执行，快速迭代
- **Recovery**：阶段总结，庆祝里程碑

**调用指令**：每个sprint结束 `/spiral checkpoint` 评估团队螺旋状态。

## 指令集

| 指令 | 功能 |
|-----|------|
| `/spiral status` | 诊断当前螺旋阶段 |
| `/spiral struggle` | 进入/确认挣扎期策略 |
| `/spiral release` | 进入释放期 |
| `/spiral flow` | 进入心流期（需满足条件） |
| `/spiral recover` | 进入恢复期 |
| `/spiral checkpoint` | 螺旋检查点，评估是否完成本轮 |
| `/spiral next` | 启动下一轮螺旋 |
| `/spiral log` | 查看螺旋历史记录 |

## 螺旋上升指标

评估螺旋质量的指标：

- **循环完整性**：四阶段是否都被经历（不跳过）
- **心流时长**：Flow期占总时间的比例
- **恢复充分度**：Recovery期是否足够（不过早启动下一轮）
- **迭代提升**：每次螺旋后技能/理解是否有提升
- **可持续性**：能否长期维持而不 burnout

## 与其他Skill的关系

- **user-as-agent**：spiral-cycle 提供任务执行的节奏框架
- **md-chain-integrity**：周期性调用 spiral-cycle 收束文档结构
- **md-chain-navigation**：螺旋上升替代线性推进，导航更灵活

## 反模式

| 反模式 | 危害 | 纠正 |
|-------|------|------|
| 线性推进强迫症 | 忽视周期律，导致burnout | 接受螺旋非线性 |
| 永久心流追求 | 跳过恢复期，螺旋质量下降 | 恢复期是必须的 |
| 挣扎期逃避 | 无法建立认知负荷，浅层学习 | 挣扎是心的前奏 |
| 释放期延长 | 变成拖延，错过心流窗口 | 设置时间盒 |
| 无记录螺旋 | 无法复盘优化，重复同样错误 | 维护spiral log |

## 结语

螺旋周期的核心认知：**任何有价值的产出都遵循挣扎-释放-心流-恢复的循环**。试图跳过任一阶段或追求直线推进，都会导致效率损失或倦怠。

正如本Skill所示范的：定期收束、周期性调用、螺旋上升。
