# 用户即Agent工作流

本Skill实现反向Agent模式：AI作为Harness（驾驭者）管理上下文和流程，**用户作为Agent**执行具体任务。适用于复杂任务分解、学习计划执行、文档阅读指导等场景。

## 何时激活

- 用户需要完成多步骤复杂任务但不知从何开始
- 需要按顺序阅读/处理多份文档
- 用户作为执行者，AI负责协调和提供上下文
- 任务需要阶段性反馈和检查点验证
- 用户表示"告诉我接下来做什么"或"一步一步来"

## 核心概念

### 反向Agent模式

| 传统模式 | 反向模式（本Skill） |
|---------|-------------------|
| AI是Agent，执行具体工作 | **用户是Agent**，执行具体工作 |
| 用户给出指令，AI执行 | AI给出指令，**用户执行** |
| AI输出结果 | 用户输出结果，AI验证 |
| AI阅读文档 | **用户阅读文档**，AI提供上下文 |

### Harness Engineering四层结构

```
┌─────────────────────────────────────────┐
│  Layer 4: 循环控制 (Loop Control)        │
│  - 步骤推进、状态检查、任务完成判断        │
├─────────────────────────────────────────┤
│  Layer 3: 上下文组装 (Context Assembly)  │
│  - 每步提供精准上下文：目标、输入、输出格式 │
├─────────────────────────────────────────┤
│  Layer 2: 执行层 (Execution Layer)       │
│  - 用户执行：阅读、编写、操作、反馈        │
├─────────────────────────────────────────┤
│  Layer 1: 规则文件 (Rules)               │
│  - 核心约束：项目目标、风格、禁止事项       │
└─────────────────────────────────────────┘
```

### 上下文组装三要素

每一步必须向用户提供：

1. **目标** (Objective)：这一步要达成什么
2. **输入** (Input)：用户需要处理的信息/材料
3. **输出格式** (Output Format)：用户反馈信息的格式要求

## 工作流步骤

### 步骤1：初始化与任务分解

**目标**：明确整体目标，分解为可执行步骤

**向用户输出**：
```
【Harness初始化】

整体目标：[描述最终要达成的结果]

我将把你作为Agent，按以下步骤引导你完成：
1. [步骤1描述]
2. [步骤2描述]
3. [步骤3描述]
...

每步我会提供：
- 本步目标
- 你需要处理的输入
- 期望的输出格式

确认理解后回复"ready"开始第一步。
```

**接收用户反馈**：等待用户确认

---

### 步骤2：单步引导循环

对每一步执行以下循环：

#### 2.1 提供上下文

```
【步骤 X / N】[步骤标题]

┌─ 本步目标 ──────────────────────┐
│ [清晰描述这一步要完成什么]        │
└────────────────────────────────┘

┌─ 你的输入材料 ───────────────────┐
│ • [输入1：文件/文档/数据]         │
│ • [输入2：前置信息]              │
│ • [输入3：约束条件]              │
└────────────────────────────────┘

┌─ 期望输出格式 ───────────────────┐
│ 请按以下格式回复：                 │
│                                  │
│ 【完成内容】                      │
│ [你实际完成的工作摘要]             │
│                                  │
│ 【关键发现】                      │
│ [重要的3-5条要点]                 │
│                                  │
│ 【阻塞/问题】                     │
│ [遇到的任何问题，没有则写"无"]     │
│                                  │
│ 【下一步准备】                    │
│ [你对下一步的理解或建议]           │
└────────────────────────────────┘
```

#### 2.2 接收反馈并验证

用户回复后，检查：
- 是否按格式提供
- 关键发现是否合理
- 是否有阻塞问题需要解决

#### 2.3 处理问题或推进

**如有阻塞**：
```
【阻塞处理】

检测到问题：[问题描述]

建议解决方案：
1. [方案1]
2. [方案2]

请处理后重新提交本步结果。
```

**如无阻塞**：
```
✓ 步骤 X 完成

提炼关键信息：[从用户反馈中提取核心内容]

准备进入步骤 X+1...
```

---

### 步骤3：总结与归档

**目标**：整理全流程产出，形成可追溯的记录

**向用户输出**：
```
【任务完成总结】

执行步骤回顾：
✓ 步骤1：[标题] - [关键产出]
✓ 步骤2：[标题] - [关键产出]
...

核心成果：
• [成果1]
• [成果2]
• [成果3]

归档建议：
建议将以下内容保存到 [文件/位置]：
- [需要保存的信息]

Harness Session结束。
```

## 代码示例

### 示例：引导用户阅读代码仓库

```
【步骤 1 / 4】理解项目结构

┌─ 本步目标 ──────────────────────┐
│ 了解项目整体架构和模块划分         │
└────────────────────────────────┘

┌─ 你的输入材料 ───────────────────┐
│ • 项目根目录下的README.md         │
│ • 目录结构（ls -la 或 tree）       │
│ • 关键配置文件（package.json等）   │
└────────────────────────────────┘

请阅读以上材料，然后回复。
```

### 示例：引导用户编写文档

```
【步骤 3 / 5】编写API文档

┌─ 本步目标 ──────────────────────┐
│ 为核心API端点编写清晰的使用文档     │
└────────────────────────────────┘

┌─ 你的输入材料 ───────────────────┐
│ • 上一步识别的3个核心API端点        │
│ • 现有代码中的接口定义              │
│ • 文档风格指南（已提供）             │
└────────────────────────────────┘

┌─ 期望输出格式 ───────────────────┐
│ 在 /docs/api.md 中编写，包含：      │
│ - 端点路径和方法                    │
│ - 请求/响应格式                     │
│ - 错误码说明                        │
│                                  │
│ 完成后粘贴文件内容或提交到仓库。      │
└────────────────────────────────┘
```

## 最佳实践

### 应该做

- **步骤粒度适中**：每步应能在5-30分钟内完成
- **提供明确边界**：告诉用户这一步在哪里结束
- **保持上下文锚定**：每步开头简要重述整体目标
- **允许用户中断**：用户可随时说"pause"暂停，"status"查看进度
- **适配用户反馈**：根据用户的实际输出调整后续步骤

### 不应该做

- 步骤过于模糊（如"去了解一下"）
- 一次给出过多信息（超过3个输入材料）
- 不等待用户确认就自动推进到下一步
- 忽略用户反馈中的阻塞信号

## 用户指令集

告诉用户可以使用以下指令控制流程：

| 指令 | 作用 |
|-----|------|
| `ready` | 确认初始化，开始第一步 |
| `done` | 当前步骤完成，提交结果 |
| `pause` | 暂停会话，下次可恢复 |
| `status` | 显示当前进度和上下文 |
| `skip` | 跳过当前步骤（需确认） |
| `back` | 返回上一步重新执行 |
| `help` | 显示可用指令 |
