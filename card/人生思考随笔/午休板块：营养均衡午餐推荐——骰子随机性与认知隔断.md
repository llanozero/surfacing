# 午休板块：营养均衡午餐推荐——骰子随机性与认知隔断

> **定位**：本文是能量六环中「修复」环（12:00-15:00）的术层实操文档。设计者负责建立菜谱库和健康指标模型，执行者负责掷骰子、吃、记录——中间不允许设计者插手。骰子不是娱乐，是认知隔断装置。

---

## 零、本文的位置

在《道：能量、承诺与意义的流通》中，修复环被定义为——**消费工作记忆占用，产出清空缓存与恢复社交带宽**。这一环的核心动作是午餐、午休、放空。

但「吃什么」这件事，天然是一个设计者最容易入侵执行者地盘的战场。

你在点餐时犹豫、在货架前徘徊、在打开外卖App后刷了二十分钟——这些都是「设计者模式」在修复环里的非法越界。修复环不需要你重新建模、比较选项、评估性价比；它只需要你把一件确定性的事做完，然后让身体和大脑真正停下来。

本文要解决的就是这件事：**把午餐从一场微型决策危机，变成一段黑盒执行。**

## 一、健康指标看板：进餐前的系统快照

在掷骰子之前，执行者需要看一眼当前的身体状态。这不是为了让执行者「决策」，而是让执行者「知道」。决策发生在设计阶段，执行阶段只有两种信息：读数与指令。

### 1.1 健康指标面板

| 指标项 | 正常区间 | 当前状态信号 | 含义 |
|--------|---------|-------------|------|
| **饥饿度** | 3-7（1-10量表） | 过低（1-2）：低血糖头晕；过高（8-10）：决策能力下降 | 决定进食优先级 |
| **饱腹感倾向** | —— | 本次更需「饱腹感强」还是「轻盈不困」 | 影响餐后能量走势 |
| **上午消耗类型** | —— | 高脑力消耗 / 高体力消耗 / 混合型 | 影响营养素需求侧重 |
| **水分状态** | 尿色淡黄 | 深黄/口干 → 需要补水优先 | 餐前先喝水 300ml |
| **下午任务预告** | —— | 协作社交 / 深度专注 / 机动待命 | 决定是否需要「稳血糖」策略 |
| **情绪基线** | 中性偏正向 | 焦虑/烦躁 → 需要温热食物安抚；低迷 → 需要明亮口感提振 | 隐性影响消化吸收 |

### 1.2 执行者的进餐前检查清单

```
□ 喝一杯水（300ml）
□ 看一眼饥饿度：现在是 ____（1-10）
□ 确认下午的主要场景：____
□ 确认当前情绪基调：____
```

**设计者提示**：以上四项中，执行者只需要填写，不需要判断。判断规则已经写在下文的「骰子映射表」里。

## 三、骰子系统：作为认知隔断的黑盒随机性

### 3.1 为什么骰子不是装饰，而是装置

在标准的能量六环设计中，修复环位于专注环之后、协作环之前，是系统中缓冲压力最大的一个交接带。这个交接带天然具有一个危险属性：**执行者的控制权尚未完全交出，设计者的反思冲动已经蠢蠢欲动。**

你在午饭时忍不住盘算下午的安排、在吃第一口时就担心热量超标、在餐后本该放空的时段里继续刷工作信息——这些都不是「不自律」，而是设计者模式在修复环的非法上线。

骰子的作用，就是用一个物理的外部的、不为你的意志所左右的随机量，**强行切断设计者在修复环的参与权。**

掷出什么，就吃什么。这不是将就，而是制度。执行者不需要在12个选项中做价值判断——那是设计阶段的事。掷骰子只需要一个动作，结果即刻产生，没有犹豫空间。

### 3.2 骰子映射规则（设计者已封装）

```
掷一次 6 面骰子。

点数 ① → 高蛋白低脂型 （A1-A3 按顺序取，缺货顺延）
点数 ② → 均衡温和型   （B1-B3 按顺序取）
点数 ③ → 高碳水续航型 （C1-C3 按顺序取）
点数 ④ → 轻盈防困型   （D1-D3 按顺序取）
点数 ⑤ → 温热修复型   （E1-E3 按顺序取）
点数 ⑥ → 高纤清体型   （F1-F3 按顺序取）
```

**顺延规则**：如果当天 A1 不可得，取 A2；A2 不可得，取 A3；A3 也不可得 → 触发骰子重掷（仅限一次）。重掷后仍不可执行 → 触发检查点，设计者介入。

**情绪覆盖规则（可选启用）**：如果进餐前健康指标面板显示情绪基线为「焦虑/烦躁」，执行者可以在掷骰子后，将结果强制映射到「温热修复型（⑤）」——这条规则本身也是设计者预设的，不是执行者临时变卦。

### 3.3 随机性作为隔断：从涌现到执行

在《分支·涌现与随机》中，扔硬币的意义被描述为：「它不在于听从结果，而在于硬币抛起的那一瞬间，你内心深处希望它是哪一面。」

但修复环的骰子与这个隐喻有一个关键的**方向反转**。

在创作和叙事场景中，随机量是用来**打破设计的僵局**——它把你从过度控制的困境中解放出来，让你重新感知真实的碰撞感。

在修复环的午餐场景中，随机量是用来**保护执行的纯粹性**——它把你从过度反思的困境中解放出来，让你免于在选择中消耗本该用于恢复的能量。

前者的随机量服务于设计者，帮助它从死胡同里找到新入口。后者的随机量服务于执行者，帮助它关掉设计者的麦克风。

**这正是两种随机性的本质差异：一种为「涌现」开路，一种为「隔断」筑墙。**

### 3.4 为什么说骰子是「黑盒」

骰子一旦掷出，执行者只能看到结果，看不到菜谱库的全貌。它不需要知道有12套方案、72个营养参数、6种场景分类。它只需要知道「现在是吃鸡胸肉沙拉的时间」。

这就是黑盒。它屏蔽了复杂性，只暴露一个入口和一个出口。正是这种屏蔽，让执行者获得了它最需要的东西：**一个不能再被质疑的行动指令。**

而密封指令机制在这里找到了它在术层的最具体实现——不是抽象的设计文档，不是项目管理软件里的状态字段，而是一个真实的、物理的、在你手心里发出响声的六面体。

## 四、餐后记录：食用影响的健康指标更新

### 4.1 进餐后30分钟的反馈记录

执行者吃完后，不需要分析，只需要记录以下四项：

```
□ 饱腹感评分：____（1-10，1=还饿，10=撑得难受）
□ 清醒度变化：____（更清醒 / 无变化 / 开始犯困）
□ 情绪变化：____（好转 / 无变化 / 更差）
□ 消化感受：____（顺畅 / 轻微胀 / 明显不适）
```

### 4.2 餐后90分钟的能量水平记录

这是午餐对下午产生真实影响的延迟反馈窗口：

```
□ 下午专注力水平：____（1-10，与平日相比）
□ 是否有「餐后低谷」：是 / 否（如果有，出现在饭后____分钟）
□ 社交意愿：____（渴望社交 / 中性 / 想独处）
□ 是否提前饿了：是 / 否（如果饿了，出现在饭后____分钟）
```

### 4.3 健康指标的变化追踪

设计者在下一次设计阶段（通常是当晚的投资环，18:00-21:00），会查看这些记录，并做以下判断：

| 观察到的模式 | 可能的调参方向 |
|-------------|---------------|
| 连续3次餐后犯困 | 降低碳水比例，或从该菜谱类型的碳水来源中替换低GI选项 |
| 连续3次饭后2小时饿 | 增加蛋白质或脂肪比例，延长饱腹时间 |
| 特定菜谱导致情绪好转 | 标记该菜谱的「情绪修复」权重，优先在情绪低迷日分配 |
| 特定菜谱导致腹胀 | 排查是否为豆类/乳制品不耐受，标记禁忌 |
| 下午社交场效果好 | 记录该日的碳水摄入量作为「社交日」的参考区间 |

这些调整发生在**设计者时段**（投资环），而不是在执行者执行午餐的当下。设计者修改的是菜谱库参数和骰子映射规则，不是当天的午餐选择。

## 五、术层运转流程：一个完整的午餐循环

### 5.1 时间线

```
12:00  执行者进入修复环
        │
        ├─ 喝水300ml
        ├─ 填写健康指标面板（30秒）
        ├─ 🎲 掷骰子（5秒）
        ├─ 根据结果取菜（如果自备则直接取，如果需要外出/外卖则出发）
        │
12:05-12:35  进食（不刷手机、不看工作信息）
        │      咀嚼次数：每口15-20下
        │      吃到7-8分饱时停止
        │
12:35-12:50  餐后静止（不立即躺下，不立即工作）
        │      散步/站立/听轻音乐/简单拉伸
        │
12:50        填写餐后反馈记录（1分钟）
        │
12:51-14:55  放空/午休/轻度恢复活动
        │      此阶段为执行者自主支配的恢复时间
        │
15:00        进入协作环，设计者重新上线
```

### 5.2 角色分工一览

| 环节 | 设计者 | 执行者 |
|------|--------|--------|
| 菜谱库维护 | ✅ 创建/修改/删除菜谱 | ❌ 无权限 |
| 骰子映射规则 | ✅ 设定映射逻辑和覆盖规则 | ❌ 无权限 |
| 健康指标面板填写 | ❌ 无权限（不可在修复环上线） | ✅ 照实填写 |
| 掷骰子 | ❌ 无权限 | ✅ 掷骰子，接受结果 |
| 进食 | ❌ 无权限 | ✅ 执行 |
| 餐后记录 | ❌ 无权限 | ✅ 照实填写 |
| 趋势分析与调参 | ✅ 在投资环（18:00-21:00）中进行 | ❌ 无权限 |

| 设计者越界行为 | 执行者的防御脚本 |
|---------------|-----------------|
| 「今天特别想吃那个……」 | 「骰子已经掷了。想吃的话，记下来，明天设计阶段把它的权重调高。今天吃骰子给的。」 |
| 「这道菜热量是不是太高了……」 | 「菜谱库里的热量区间是设计者校准过的。如果觉得不对，今晚投资环提修改。现在吃。」 |
| 「要不要换个外卖平台比较一下……」 | 「不比较。顺延规则已经写好了。材料不可得就顺延下一项。」 |
| 「下午好像没什么事，要不要少吃点……」 | 「健康指标面板已经填过了。'下午任务预告'对骰子映射的影响已经在设计阶段处理。现在吃骰子给的。」 |

## 六、延伸思考：这个系统中到底什么是「设计」

读到这里，一个自然的疑问是：如果骰子结果不可控，那设计者的价值在哪里？

答案是：**设计者不设计午餐，设计者设计「选择午餐的系统」。**

设计者的工作产物不是「今天中午吃什么」的答案，而是：

- 一个经过校准的 12 套菜谱库；
- 一套基于身体状态的骰子映射规则；
- 一个餐后反馈的数据收集框架；
- 一个每周趋势分析的调参机制。

这些产物在修复环到来之前就已经封装完毕。修复环只需要执行，不需要设计。

而这恰恰是「设计者与执行者分离」在术层的最具体呈现：**设计者写的不是答案，是让答案不再需要被反复思考的制度。**

骰子是这个制度中最直观的一个组件。它把选择权从意识层面移到了物理层面，从一个可以不断回旋的思维空间，移到了一个不可逆的力学事件。你可以在掷之前犹豫，但掷出之后，骰子不说话，它只是朝上。
