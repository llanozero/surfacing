# BDI模型设计：信念-欲望-意图架构

## 模型概述

BDI (Belief-Desire-Intention) 模型是实现"构建式交互"的核心框架,它提供了从知识到行动的清晰推理路径。

## 三层架构

### 1. 信念层 (Beliefs Layer)

**定义**: 系统的知识库,代表"已知的事实"和"外在逻辑"

#### 信念的来源
- **科学数据**: 经过验证的研究结果
- **经验规则**: 历史行为的总结
- **环境约束**: 现实条件的限制
- **资源状态**: 可用的时间、精力、工具

#### 信念的结构
```json
{
  "belief_id": "B001",
  "category": "时间管理",
  "content": "人类专注力通常在25-45分钟后下降",
  "confidence": 0.85,
  "source": "科学研究",
  "last_updated": "2025-11-11"
}
```

#### LLM在信念层的作用
- **知识提取**: 从文本中提取结构化信念
- **知识验证**: 检查信念的一致性和冲突
- **知识更新**: 根据新信息更新信念库
- **知识检索**: 根据上下文快速找到相关信念

### 2. 欲望层 (Desires Layer)

**定义**: 系统的目标和偏好,代表"想要达成的状态"

#### 欲望的类型
- **终极目标**: 长期的、抽象的愿景
- **中期目标**: 具体的、可衡量的里程碑
- **即时目标**: 短期的、具体的任务

#### 欲望的属性
```json
{
  "desire_id": "D001",
  "type": "中期目标",
  "description": "在3个月内建立稳定的运动习惯",
  "priority": 8,
  "deadline": "2026-02-11",
  "success_criteria": [
    "每周运动至少3次",
    "每次运动至少30分钟",
    "连续坚持12周"
  ],
  "motivation": "提高身体健康和精力水平"
}
```

#### 欲望的冲突解决
- **优先级排序**: 根据重要性和紧急性
- **资源分配**: 评估时间和精力的分配
- **目标协调**: 识别和解决相互冲突的目标

### 3. 意图层 (Intentions Layer)

**定义**: 系统承诺执行的具体计划,是从信念和欲望"构建"出来的行动方案

#### 意图的生成过程
```
1. 选择一个欲望(D)
2. 检索相关信念(B)
3. 评估可行性: B ∩ D → 可行性分数
4. 如果可行性 > 门槛:
   - 构建具体计划
   - 分解为行动步骤
   - 设定检查点
5. 形成意图(I)
```

#### 意图的结构
```json
{
  "intention_id": "I001",
  "desire_ref": "D001",
  "belief_refs": ["B001", "B023", "B045"],
  "plan": {
    "phase": "执行中",
    "steps": [
      {
        "step_id": 1,
        "action": "选择运动类型(慢跑)",
        "status": "completed",
        "executor_mode": "设计者"
      },
      {
        "step_id": 2,
        "action": "制定每周时间表",
        "status": "completed",
        "executor_mode": "设计者"
      },
      {
        "step_id": 3,
        "action": "执行运动计划",
        "status": "in_progress",
        "executor_mode": "执行者",
        "sealed": true,
        "no_modification_until": "2025-11-25"
      }
    ]
  },
  "checkpoints": [
    {
      "date": "2025-11-25",
      "type": "两周回顾",
      "evaluator": "设计者"
    }
  ]
}
```

## 门槛筛选机制

### 筛选维度

1. **可行性检查**
   - 是否有足够的资源?
   - 是否与现有信念冲突?
   - 是否在能力范围内?

2. **优先级评估**
   - 与其他欲望的相对重要性
   - 时间敏感度
   - 长期价值

3. **风险评估**
   - 失败的可能性
   - 失败的代价
   - 可逆性

### 门槛公式
```
可行性分数 = w1 × 资源充足度 + w2 × 信念一致性 + w3 × 能力匹配度
通过门槛 = (可行性分数 > θ) AND (优先级 > π) AND (风险 < ρ)
```

## LLM驱动的实现

### Prompt设计策略

#### 1. 信念提取Prompt
```
角色: 你是一个知识提取专家
任务: 从以下文本中提取可作为"信念"的事实性陈述
要求:
- 只提取可验证的事实
- 标注置信度(0-1)
- 标注来源类型(科学研究/经验/常识)
输入: [用户文本]
输出: JSON格式的信念列表
```

#### 2. 意图构建Prompt
```
角色: 你是一个行动规划专家
任务: 基于给定的欲望和信念,构建可执行的意图
输入:
- 欲望: [目标描述]
- 相关信念: [信念列表]
要求:
- 评估可行性(0-1分)
- 如果可行性>0.7,生成详细计划
- 明确标注哪些步骤需要"设计者"模式,哪些需要"执行者"模式
- 设定合理的检查点
输出: JSON格式的意图对象
```

#### 3. 冲突检测Prompt
```
角色: 你是一个逻辑一致性检查器
任务: 检查新信念/欲望是否与现有系统冲突
输入:
- 新项目: [新信念或新欲望]
- 现有系统: [相关信念和欲望列表]
输出:
- 冲突列表
- 冲突严重程度
- 解决建议
```

## 数据流图

```
用户输入
    ↓
[LLM: 理解与分类]
    ↓
  信念? ──→ 信念库 ──┐
    ↓                 ↓
  欲望? ──→ 欲望库 ──→ [LLM: 意图构建]
                      ↓
                  门槛筛选
                      ↓
                  通过? ──No──→ 反馈用户
                      ↓ Yes
                  意图库
                      ↓
                  执行调度
```
