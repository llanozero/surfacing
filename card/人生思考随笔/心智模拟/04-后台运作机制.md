# 后台运作机制：长滞后与潜意识模拟

## 核心概念

**后台运作**: 系统在用户"不操作"、"不关注"时继续处理问题,模拟潜意识的工作方式。

**长滞后**: 执行效果不是立即显示,而是在一段时间后才反馈给设计者。

## 理论基础

### 爱迪生的钢球技巧
1. **设定问题**: 意识层面明确要解决的问题
2. **状态切换**: 通过入睡,意识下线
3. **后台处理**: 潜意识在睡眠边缘自由联想
4. **中断捕获**: 钢球落地,唤醒意识
5. **结果收割**: 立即记录潜意识的产出

## 系统设计

### 1. 后台任务类型

#### A. 创意孵化任务
- 适用于需要灵感、创新思维的问题
- 孵化期: 24-72小时
- LLM使用高temperature参数生成多样化方案

#### B. 习惯强化任务
- 静默记录执行数据
- 7-14天后才显示分析结果
- 避免过度关注导致的焦虑

#### C. 问题酝酿任务
- 复杂决策需要"睡一觉再说"
- 后台从多角度分析
- 3-7天后呈现综合建议

### 2. 长滞后实现机制

#### 时间维度
- **短滞后**(数小时): 创意灵感、情绪冷却
- **中滞后**(数天): 习惯养成、问题酝酿
- **长滞后**(数周): 长期目标评估

#### 触发条件
- 时间到期自动触发
- 用户主动查询
- 检测到相关上下文活动

### 3. 中断与唤醒机制

模拟"钢球落地"的唤醒时刻:
- 关键时间点提醒
- 环境线索触发
- 进度阈值达成

## LLM的后台角色

### 异步处理流程
1. 接收任务并存储
2. 在后台定期运行推理
3. 累积中间结果
4. 到期时整合输出

### Prompt设计
```
你是一个后台思考助手。
任务: [问题描述]
要求: 从多个角度分析,不要急于给出答案
时间: 你有48小时的"思考时间"
输出: 在48小时后提供综合分析
```

## 技术实现

### 任务调度系统
- 使用任务队列(如Celery)
- 定时触发后台LLM推理
- 结果缓存直到展示时机

### 数据库设计
```sql
CREATE TABLE background_tasks (
    id UUID PRIMARY KEY,
    task_type VARCHAR,
    input_data JSONB,
    status ENUM('incubating', 'ready', 'delivered'),
    created_at TIMESTAMP,
    ready_at TIMESTAMP,
    intermediate_results JSONB
);
```

## 用户体验设计

### 设定阶段
"我会在后台思考这个问题,48小时后给你答案。期间请不要过度关注,去做其他事情。"

### 等待阶段
- 最小化提醒
- 鼓励用户"遗忘"
- 可选的进度隐藏

### 收割阶段
"时间到了!这是我在后台为你准备的分析..."
