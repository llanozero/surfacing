## 应用界面对应

### 导航和入口
- 主导航：系统中心导航，提供快速访问各个模块的入口。
- 晨间任务扫描：5分钟决策树，用于快速分类和处理待办任务。
- 快速参考卡片：手机端快速查看，提供便捷的操作指南。

### 四个阶段
- 执行单元：稳态行动，确保日常任务的稳定执行。
- 高难度拆解：高消耗区，处理复杂任务时的策略指引。
- 高沉迷恢复：能量补给，帮助恢复精力和专注。
- 回到执行单元：稳定落地，确保任务完成后的状态恢复。

### 八个场景
- 深度探索的迷宫：高挑战场景，适合深入分析和解决问题。
- 激烈的解谜游戏：高强度场景，适合快速思考和决策。
- 西西弗斯的苦役：低效场景，提醒避免重复无效的努力。
- 吞青蛙：高优先级任务，适合优先处理重要事项。
- 多巴胺沼泽：低效场景，提醒避免分心和过度娱乐。
- 零食碎片：小任务场景，适合处理琐碎的日常事务。
- 流水线工位：常规任务场景，适合日常工作的稳定推进。
- 两分钟任务：快速任务场景，适合快速完成的小任务。

### 文档
- README.md：文件结构和使用指南，帮助用户快速上手和理解系统。

### 使用方式
- 日常使用流程：
  1. 早上打开晨间任务扫描。
  2. 用决策树快速分类待办任务。
  3. 按照场景进入对应的执行模式。
  4. 需要快速查询时，打开快速参考卡片。

## 8个场景 × 4个阶段：映射方案（每阶段2个场景）

### 约束（你给的硬约束）

1. **高难度拆解**：必须是“高难”。
2. **高沉迷恢复**：必须是“高瘾”。
3. **回到执行单元**：必须是“长时”。
4. **执行单元**：你给出的锚点是“低难 + 低瘾 + 短时”。（现实里要做到每阶段2个场景，第二个通常需要按“最相近/最常用入口”来补位，否则会出现只有一个场景能严格满足。）

为避免“一个场景同时满足多个阶段条件”导致冲突，下列方案把阶段理解为：**更推荐的入口/操作形态**，而不是场景的唯一归属。

---

### 方案A（优先满足：拆解=高难、恢复=高瘾、回到执行=长时）

| 阶段 | 对应场景（2个） | 说明 |
| :--- | :--- | :--- |
| 执行单元 | 场景8 两分钟任务；场景6 零食碎片 | 都是“短时”，适合直接进入执行；场景6 虽然是高瘾，但操作上更像“批量执行/批量清零”的执行工位入口。 |
| 高难度拆解（必须高难） | 场景1 深度探索的迷宫；场景4 吞青蛙 | 场景1 长周期高复杂，拆解是主航道；场景4 短周期但高难且痛苦，先拆解能显著降低启动阻力。 |
| 高沉迷恢复（必须高瘾） | 场景2 激烈的解谜游戏；场景5 多巴胺沼泽 | 二者都是高瘾；区别是场景2“可用的高瘾”（可转化为产出），场景5“危险的高瘾”（需要防御性恢复）。 |
| 回到执行单元（必须长时） | 场景3 西西弗斯的苦役；场景7 流水线工位 | 都是长时；通过封装/流程化把长周期任务重新压回可执行的稳态节律。 |

---

### 方案B（更贴近“阶段语义”，把长时的高瘾也当作需要‘回扣’的对象）

| 阶段 | 对应场景（2个） | 说明 |
| :--- | :--- | :--- |
| 执行单元 | 场景8 两分钟任务；场景7 流水线工位 | 都是低难低瘾（场景7为长时版本），执行单元强调“稳态推进”，场景7放这里表示：其默认处理方式是执行而非拆解/恢复。 |
| 高难度拆解（必须高难） | 场景1 深度探索的迷宫；场景3 西西弗斯的苦役 | 两者都是高难+长周期；用拆解把长期复杂/长期苦役变成可推进的结构与节拍。 |
| 高沉迷恢复（必须高瘾） | 场景2 激烈的解谜游戏；场景6 零食碎片 | 都是高瘾+短周期；场景6放这里表示：它虽然“看起来像执行”，但本质是注意力碎片，需要通过恢复/防御机制把上瘾性收束。 |
| 回到执行单元（必须长时） | 场景5 多巴胺沼泽；场景4 吞青蛙 | 场景5是高瘾长时，必须靠“回到执行”做强制封装/回扣；场景4虽然短时，但作为“必须尽快收束”的任务，把它放在回到执行强调：完成后立刻封装并回到稳态，避免拖成长期消耗。 |

---

### 方案C（最严格版本：把执行单元只绑定‘低难低瘾短时’，其余按硬约束填满）

该方案的特点是：**执行单元只有一个场景能严格满足**（场景8），因此第二个位置只能选“最接近的短时入口”作为补位。

| 阶段 | 对应场景（2个） | 说明 |
| :--- | :--- | :--- |
| 执行单元 | 场景8 两分钟任务；场景4 吞青蛙 | 场景4不满足“低难”，但它最需要“立刻开始+短时收束”的执行姿态，所以用它来补位执行单元入口。 |
| 高难度拆解（必须高难） | 场景1 深度探索的迷宫；场景2 激烈的解谜游戏 | 场景2虽短时，但高难高瘾，拆解能防止上头式乱撞，提高解谜效率。 |
| 高沉迷恢复（必须高瘾） | 场景5 多巴胺沼泽；场景6 零食碎片 | 都是低难高瘾，恢复侧重点是“防御/收束/回扣”。 |
| 回到执行单元（必须长时） | 场景3 西西弗斯的苦役；场景7 流水线工位 | 两个都是长时低瘾（一个高难一个低难），回到执行的核心是封装节拍与可见证据，防止长期磨损。 |

---

### 你可以如何选择方案

1. **如果你把“阶段”当作操作界面入口**：用方案A（最直观、最像导航）。
2. **如果你更关心“注意力风险管理（高瘾都需要收束）”**：用方案B（把零食碎片视为高瘾问题）。
3. **如果你想把约束当作硬分类并接受补位**：用方案C。

## 三个方案的记叙文小说描写（阶段×场景×状态值变化）

状态值约定：

- **能量E**：0-100（越高越有力）
- **阻力R**：0-100（越高越难启动）
- **沉迷A**：0-100（越高越容易停不下来）

### 方案A：像导航一样跑完一圈

他把计时器放在桌角，像给自己盖了章。起步是**执行单元**，他先挑最小的口子下刀：两分钟任务、零食碎片，一口一口吞下去。每完成一个小块，他都听见任务列表发出轻微的“咔哒”声。

- **执行单元（场景8→场景6）**
  - 初始：E70 / R20 / A30 / C55 / O10
  - 场景8清零后：E72 / R15 / A25 / C60 / O18
  - 场景6批量处理后：E68 / R18 / A45 / C62 / O28

然后，他抬头看见那座更大的山：**吞青蛙**。阻力像铁锈一样爬满手指。他没硬扛，直接切进**高难度拆解**。他把“青蛙”剖开：前置条件、第一步、失败代价、验证方式，一张小地图在纸上成形。

- **高难度拆解（场景4→场景1的拆解姿态）**
  - 进入时：E68 / R55 / A25 / C45 / O28
  - 拆解完成：E60 / R32 / A20 / C75 / O40

地图有了，但他也明显变慢。大脑开始发热，注意力像被砂纸磨过。他允许自己进入**高沉迷恢复**，选了“可用的高瘾”：激烈的解谜游戏，让心流把他从僵硬里拽回来；同时给沼泽立了边界，沼泽只允许站在岸边看。

- **高沉迷恢复（场景2→场景5的防御意识）**
  - 进入时：E60 / R32 / A35 / C75 / O40
  - 解谜心流后：E74 / R20 / A70 / C70 / O42
  - 沼泽防御收束后：E70 / R18 / A45 / C72 / O45

最后是**回到执行单元**。他把拆解结果压成“下一步一句话”，把今天的坑写成一条规则，贴在屏幕边缘。点击回链，系统又把他送回稳态。

- **回到执行单元（场景3/7的“长时封装”语气）**
  - 进入时：E70 / R18 / A45 / C72 / O45
  - 封装后：E66 / R12 / A25 / C80 / O60

### 方案B：把“高瘾”当作风险资产来管理

这一次他更谨慎。执行单元仍然从两分钟任务起步，但他把“流水线工位”也当作执行姿态：不求兴奋，只求稳定推进。节拍一旦对齐，阻力就像被悄悄抽走。

- **执行单元（场景8→场景7）**
  - 初始：E65 / R25 / A25 / C50 / O8

遇到长期高难，他直接进拆解：迷宫与苦役都不靠意志硬推，先把结构做出来。拆解在这里像把夜里乱跑的狗拴回牵引绳。

- **高难度拆解（场景1→场景3）**

### 方案C：硬分类下的“补位”，像在规则边缘行走

他决定严格一点：执行单元只承认“低难低瘾短时”。于是起步几乎只剩**两分钟任务**。但现实不配合，吞青蛙在门口等他，像一块必须搬走的石头——补位出现了：把吞青蛙当作“执行单元的强制启动”，先骗自己动起来。

- **执行单元（场景8→场景4补位）**
