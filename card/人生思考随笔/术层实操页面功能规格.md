# 术层实操页面功能规格

> 路径：`/#/practice-loop`
> 视图组件：`PracticeLoopWorkbenchView.vue`
> 适用：能量六环 × GTD 主链 × PARA 知识库层在「手动执行」这一层的统一入口

## 一、定位与边界

术层实操页是**手动执行层**——它把"何时做"和"做什么"具象化。

- **道层（`/#/concept-loop`）**：讲理念与地图
- **术层（本页）**：讲工具与流程
- **通用工具面板（`WorkbenchPanel`）**：把"今天凑齐一组想用的工具"作为灵活装配台

核心心智：**"到点进入板块，按固化流程跑"**。

---

### 1.1 关于"重复造工具"的辨析

术层表面上"重复造"了工具——早间规划有自己的收件箱入口、自己的待办、自己的资料初选，而通用工具面板里也都有这些。但这是**有意为之**：

| 维度 | 术层 | 通用工具面板 |
|------|------|-------------|
| 阶段 | **前期 · 固化流程** | **后期 · 灵活装配** |
| 状态 | 流程尚未稳定，需要被引导 | 流程已稳定，用户有自由组合需求 |
| 目的 | 强制把对的步骤跑完 | 让用户挑当下要的工具 |
| 心智 | "到点按剧本走" | "我今天想用这几样" |
| 关系 | 包含/约束 | 释放/延伸 |

**这不是重复，而是分层**——术层是为新手期和固化期服务的剧本，通用工具面板是熟练期和稳定期的工具台。

当某个流程被反复跑通、不再需要被引导时，它就会从术层"毕业"，下沉到通用工具面板的灵活装配位；术层一旦发现某步骤用户已经能稳定执行，就会把它的入口松开，让用户能跳出去自由组合。

更直白地说：

> 通用工具面板是术层流程**稳定之后**的延伸位；
> 术层是**尚未稳定之前**的固化训练场。

两者的方向相反：通用工具面板允许"自由组合"，术层强制"按序执行"。前期必须把流程跑熟，后期才有可能拆开重组——这是 GTD 这类方法论能落地的基本前提。

## 三、六环 × 工作台组件

每个能量环对应一个独立工作台组件，承担该环的所有 GTD 步骤落地。

| 环 | 组件 | tagline | 核心动作 |
|----|------|---------|---------|
| 睡眠 | `SleepWorkbench.vue` | 离线整合 · 后台编译 | 倒计时、入睡捕获、轻量 PARA |
| 早间规划 | `PlanWorkbench.vue` | 建立地图 · 启动与调度 | 5 步：收集 → 理清 → 组织 → 资料初选 |
| 专注 | `FocusWorkbench.vue` | 深度产出 · 核心计算 | 沉浸专注 + 番茄 + 临时捕获 |
| 午休 | `RestoreWorkbench.vue` | 系统清空 · 垃圾回收 | 午休倒计时 + 营养平衡 + 快速睡眠 |
| 协作 | `CollabWorkbench.vue` | 验证表达 · 输入输出 | 反馈捕获 + 协作笔记 |
| 投资 | `InvestWorkbench.vue` | 解构升维 · 迭代升级 | 复盘 + 规则推演 + 理论可视化 |

## 四、早间规划环（PlanWorkbench）详细规格

`PlanWorkbench.vue` 是**最重的板块**，按 GTD 五步展开为可点击的步骤条（`.stepper`），每步独立面板：

| 步骤 | 步骤 ID | 子组件 | 输入 | 输出 |
|------|---------|--------|------|------|
| 收集 | `collect` | 内联 | 睡眠/外部 inbox 条目 | 标记 included，写入草稿 |
| 理清 | `clarify` | `PracticeClarifyPanel` | inbox 队列 | 转待办 / 入 PARA / 丢弃 |
| 组织 | `organize` | 内联 | 待办池 | Top3 选中（每日限额 3 条） |
| 资料初选 | `para-pick` | `ParaReferencePicker` | Top3 任务 | 每个任务挂载 PARA 引用 |
| 完成态 | — | 横幅 | — | 提示可切专注环 |

### 4.1 资料初选工作台（ParaReferencePicker）

`ParaReferencePicker.vue` 是 P4 步骤的核心 UI，承担 **"为今日 Top3 任务预选参考资料"** 的交互。

**布局（桌面优先）：**

```
┌──────────────────────────────────────────────────┐
│ [Top3-任务1 (3)] [Top3-任务2 (1)] [Top3-任务3 (0)] │  ← top3-bar
├────────────────────┬─────────────────────────────┤
│  [📁目录树][🔍搜索]  │  📎 已选参考资料 (1 份)         │
│  排序: [类型][文件名] │  ─ 资料A ✕                    │
│ ┌────────────────┐ │  👁 预览                      │
│ │▼📥 收件箱 (5)   │ │  ┌─────────────────────────┐ │
│ │  📂 子目录      │ │  │ 路径: project/...md     │ │
│ │  📄 直接文件    │ │  │                          │ │
│ │▼📁 项目 (12)   │ │  │ 内容...                 │ │
│ │  ...            │ │  │                          │ │
│ └────────────────┘ │  └─────────────────────────┘ │
│  (可滚动)            │  (右上滚动 / 右下滚动)         │
└────────────────────┴─────────────────────────────┘
[ 完成资料初选 ]
```

**左侧 = TAB 切换 + 滚动区：**
- **目录树 TAB**：按 PARA 五分类（inbox/project/area/resource/archive）折叠展开；每个分类下子目录与同级文件混合展示，**目录优先排在同级文件上方**；点击文件名进入预览；点击 `+` 加入已选，`-` 移除
- **搜索 TAB**：实时搜索文件名和路径，结果可加可预览
- **排序**：类型（按文件夹类型分组后文件名升序）/ 文件名（全局升序）

**右侧 = 上下两段：**
- **右上：已选参考资料**——可滚动列表，显示该任务挂载的全部 PARA 引用
- **右下：预览区**——可滚动内容显示当前选中文件的全文

**Top3 切换**（顶部）：点击切换不同任务，每个任务独立维护已选列表。`refsTick` 计数确保引用变化时 UI 同步。

**完成态**：点击"完成资料初选"调用 `completeParaPickStep()`，把 `plan_ready_for_focus` 置 true，专注环可读这个状态。

### 4.2 PlanWorkbench 内核交互

```ts
// 步骤状态机
type PlanStepId = 'collect' | 'clarify' | 'organize' | 'para-pick'

// 状态机写入
completeCollectStep()    // 收集步骤
completeClarifyStep()    // 理清步骤
completeOrganizeStep()   // 组织步骤
completeParaPickStep()   // 资料初选步骤
```

**Top3 选择**：用户可手动勾选 3 条，Agent 在 `plan-llm` 工具中给出建议但需用户确认。

**PARA 引用**：
- 服务层 `todoParaRefsService.ts` 维护 `TodoId → ParaRef[]` 映射
- 引用数据结构：`{ path, title, category }`
- 标题自动从路径提取（`titleFromParaPath`）

## 五、专注工作环（FocusWorkbench）规格

| 子模块 | 用途 |
|--------|------|
| `focus-immersive` | 单任务全屏番茄，屏蔽干扰 |
| `focus-timer` | 25 分钟倒计时 |
| `focus-todo` | 从 Top3 选当前任务 |
| `focus-notes` | 执行过程记录 |
| `sys-todolist` | 完成态勾选 |
| LLM Agent | `engage-focus` workflow：推荐下一项 |

专注环**禁止**做理清与组织。中途的想法只走 `sys-inbox` 临时捕获，不打断专注流。

## 六、午休修复环（RestoreWorkbench）规格

`RestoreWorkbench.vue` 集成 3 个子面板：

| 面板 | 组件 | 用途 |
|------|------|------|
| 午休倒计时 | `restore-timer` | 20-30 分钟小憩控制 |
| 营养平衡 | `NutritionBalancePanel.vue` | 午餐建议（颜色搭配、热量、营养素） |
| 快速睡眠 | `NapQuickSleepPanel.vue` | 短小憩引导 |

**专属原则**：极低损耗地度过中场。**不做**高算力决策，只清空工作记忆 + 处理两分钟可判定项。

## 八、投资复盘环（InvestWorkbench）规格

**6 个理论可视化组件**是该环特色：

| 组件 | 可视化形式 |
|------|----------|
| `InvestTheoryTree.vue` | 树形图 |
| `InvestTheoryTreemap.vue` | 矩形树图 |
| `InvestTheoryRadialTree.vue` | 辐射树 |
| `InvestTheoryTechTree.vue` | 科技树 |
| `InvestTheoryTangledTree.vue` | 缠绕树 |
| `InvestTheoryEdgeBundling.vue` | 边绑定图 |

**GTD 步骤落地**：

| 步骤 | 入口 |
|------|------|
| 复盘 Agent | `review-day` workflow（汇总 + 改进建议） |
| 复盘笔记 | `invest-notes`（手写复盘与颗粒化） |
| 回流捕获 | "回流：" 前缀触发 `reflow` workflow（未完成/新想法） |

| PARA 提纯 | 更新 area/resource，归档 project |

**规则推演器**（`invest-ruleinfer`）和**人际推演**（`invest-simulation`）是知识晶体深化的特色工具。

## 九、睡眠环（SleepWorkbench）规格

`SleepWorkbench.vue` 是**最简**的板块：

- 21:00 入睡倒计时
- 睡前捕获：把焦虑/未竟念头记入收件箱（不深度组织）
- PARA 笔记库（仅做轻量记录）

**禁止**：理清、组织、新决策。所有内容推到下一日 plan 环处理。

## 十、关键技术约束

### 10.1 数据流
- **状态层**：`planWorkbenchService.ts` 管理 PlanWorkbench 状态机
- **引用服务**：`todoParaRefsService.ts` 管理 TodoId → ParaRef 映射
- **PARA 库**：`paraLibraryService.ts` 对接后端 `/api/files`、`/api/file`
- **Agent 桥接**：`PENDING_LLM_WORKFLOW_KEY` 在 `localStorage` 暂存待执行的 LLM workflow

### 10.2 路由与跳转

| 跳转 | 触发 |
|------|------|
| 仪表盘 → 术层 | `/` 上点击能量环 |
| 道层 → 术层 | 顶部导航"道层导览" |
| 早间 → 专注 | `plan_ready_for_focus=true` 后顶部"今日规划已完成"提示 |
| 工具 → LLM | `PENDING_LLM_WORKFLOW_KEY` 携带 workflow 名 |
| 任何 → `sys-llmchat` | 点击带 `kind: 'llm-workflow'` 的按钮 |

### 10.3 布局契约

页面用 flex 列布局。`workbench-main` 占用顶部 3 份空间，确保各环工作台有充分高度。

`PlanWorkbench` / `FocusWorkbench` / `InvestWorkbench` 等重型工作台内部均**不**约束父级高度，避免链路截断；其内部需要滚动的容器（文件列表、预览区）用 `overflow-y: auto` + 固定 `height` 触发内部滚动。

`ParaReferencePicker` 的 `.main-layout` 固定 `height: 800px`，三段独立滚动：

| 区 | 高度 | 滚动 |
|----|------|------|
| 左侧 TAB 内容 | ≈ 770px | ✓ |
| 右上已选 | 180px 固定 | ✓（长任务时） |
| 右下预览 | ≈ 610px | ✓ |

### 10.4 浏览器兼容
- 桌面优先（max-width: 1100px 居中）
- 移动端回退（`.main-layout` 在 ≤ 900px 切换为单列）
- 暗色主题：滚动条 6px 暗色 + 紫色 hover 态
