# 行为库与状态指标：算法式心智流转与类黑盒随机性的认知隔断

> **定位**：本文从 MindFlow 项目的实际代码和数据结构出发，梳理「行为库-状态指标-行为链-随机扰动」这套心智模拟系统的设计理念和已有实现。系统尚且粗糙，但骨架清晰，可以作为后续迭代的参考地图。

---

## 一、从菜谱到行为库：同一套抽象的两种实例

在「午休板块：营养均衡午餐推荐」中，菜谱库扮演的是一个**预设选择空间**——设计者预先封装好 12 套方案，执行者掷骰子决定吃哪一套，不需要实时决策。

MindFlow 里的行为库，是同一套抽象在心智操作层面的实例化。

| 午餐系统的元素 | MindFlow 中的对应物 | 说明 |
|---------------|-------------------|------|
| 菜谱 | **Event（事件模板）** | 一段可执行的行为指令，附带对状态的影响 |
| 菜谱的营养成分表 | **delta（状态变化量）** | 执行后对各维度的数值影响 |
| 菜谱的适用场景 | **tags（标签）+ content（描述）** | 标注该事件适用于什么情况 |
| 骰子映射规则 | **decision_trees（决策树）+ sequences（序列）** | 按什么顺序调用哪些事件 |
| 餐后反馈记录 | **state_change（状态变更记录）** | 执行前后的差异追踪 |

行为库不是菜谱的替代品，而是**同一种设计模式在不同领域的展开**——用一个预先封装好的、带有明确输入输出规范的选择空间，替代执行时的临时决策。

## 二、状态指标体系：三层维度的心智快照

在 MindFlow 的实现中，状态指标被组织成三个层次，这是从实际心智体验中提炼出来的结构。

### 2.1 主观层（subjective）

| 指标 | 默认值 | 范围 | 含义 |
|------|--------|------|------|
| **情绪** | 60 | 0-100 | 整体情感基调 |
| **专注** | 60 | 0-100 | 注意力聚焦程度 |
| **动力** | 55 | 0-100 | 行动意愿强度 |
| **压力** | 45 | 0-100 | 心理负担水平 |
| **精力** | 60 | 0-100 | 体力和认知带宽 |

这五个维度构成了对心智状态的「第一人称感知快照」。它们不可被外部仪器直接测量，但个体能清晰感知。

### 2.2 客观层（objective）

| 指标 | 默认值 | 范围 | 含义 |
|------|--------|------|------|
| **睡眠时长** | 80 | 0-100 | 前一晚的睡眠质量 |
| **运动步数** | 20 | 0-100 | 身体活动水平 |

这两个指标是可被量化追踪的外部变量，它们对主观层有明确的**因果影响力**——缺觉导致专注下降、运动不足导致精力低迷。

### 2.3 激素层（hormone）

| 指标 | 默认值 | 范围 | 含义 |
|------|--------|------|------|
| **多巴胺** | 60 | 0-100 | 奖励预期与驱动力 |
| **皮质醇** | 40 | 0-100 | 应激激素水平 |
| **血清素** | 70 | 0-100 | 情绪稳定与满足感 |

激素层是连接生理与心理的**中间变量**。它既不是纯粹的主观感受（可以被行为干预），也不是简单的客观数据（它直接影响主观体验）。在系统的因果链中，激素层充当了「行为 → 激素变化 → 主观感受」的中介。

### 2.4 三层的关系

```
客观层（睡眠、运动）
    ↓ 因果影响
激素层（多巴胺、皮质醇、血清素）
    ↓ 因果影响
主观层（情绪、专注、动力、压力、精力）
```

这个分层不是装饰性的。它决定了**哪些状态变量是可直接操控的（客观层），哪些是间接干预的（激素层），哪些是结果而非原因（主观层）**。

在行为库的设计中，一个行为（事件）对这三层的影响可以是多向的。例如：

| 事件 | 主观层变化 | 激素层变化 |
|------|-----------|-----------|
| 密封指令确认并启动 | 动力+1，专注+1 | —— |
| 高沉浸恢复 | 精力+8，情绪+5，压力-4 | 皮质醇-5，血清素+4 |
| 向可信的人求助 | 情绪+4，压力-5 | 皮质醇-4，血清素+2 |
| 后台孵化设定 | 情绪+2，压力-3 | 皮质醇-4 |
| 呼吸重置 | 专注+4，压力-8 | —— |

## 三、行为（事件）的完整定义：不只是指令，是状态变更协议

在 MindFlow 的 YAML 数据中，一个行为（事件）的完整定义包含以下字段：

```yaml
- id: evt_phase_immersive_recover
  name: 四阶段-高沉浸恢复(能量补给)
  type: leaf
  tts_cont: 现在进入高沉浸恢复：必须高上瘾，才能快速补能，但要受控...
  seconds: 4
  cooldown_events: 0
  delta:
    精力: 8
    情绪: 5
    压力: -4
    皮质醇: -5
    血清素: 4
  tags:
  - 心智模拟
  - 四阶段
  - 高沉浸恢复
  content: 用受控的高瘾活动补能，避免坠入无底洞。
```

这个定义的精妙之处在于：**每个事件不仅是一个行为指令，还是一个状态变更协议。** 它预先声明了执行后各维度应该发生什么变化。

### 3.1 delta 的算法式意义

delta 不是静态的数字，它在系统中扮演以下角色：

1. **预期参考**：执行者执行后，实际状态变化可以与 delta 做对比，验证事件是否有效；
2. **路径规划的依据**：当系统需要规划一条行为链时，它可以根据各事件的 delta 来计算哪条链能最快抵达目标状态；
3. **条件触发器的输入**：overlay（覆盖层）规则会检查当前状态，并在特定条件下对 delta 进行乘数修正。

### 3.2 条件规则与状态叠加

系统中存在一种称为 **overlay（覆盖层）** 的机制，它允许在特定状态下对行为效果进行修正。例如：

```yaml
state_overlays:
  - id: overlay_sleep_deprived
    schema_id: mind_basic_v1
    name: 缺觉模式
    rules:
      - id: sleep_deprived_focus_penalty
        priority: 200
        when:
          all:
            - key: objective.睡眠时长
              op: lt
              value: 45
        apply:
          - match_intent: focus_gain
            op: multiply
            value: 0.75
          - match_intent: energy_gain
            op: multiply
            value: 0.8
        message: 缺觉时，专注和精力恢复效率下降
```

这条规则的含义是：当客观层的睡眠时长低于 45 时，所有意图为「专注提升」的行为，其效果打 0.75 折；所有意图为「精力恢复」的行为，其效果打 0.8 折。

这就构成了一种**算法式的影响叠加**：

```
基础行为 delta
  → 经过 effect_mapping 映射到具体指标
    → 经过 schema rules 的条件乘数修正
      → 经过 overlay rules 的状态条件修正
        → 最终状态变化
```

### 3.3 effect_mapping：意图到指标的桥

在状态 schema 中，存在一种称为 effect_mapping 的映射机制，它把行为的「意图类型」翻译成「对具体指标的操作」：

```yaml
effect_mapping:
  focus_gain:
    target: subjective.专注
    op: add
    ratio: 1.0
  stress_relief:
    target: subjective.压力
    op: add
    ratio: -1.0
  energy_gain:
    target: subjective.精力
    op: add
    ratio: 1.0
  mood_gain:
    target: subjective.情绪
    op: add
    ratio: 1.0
```

这意味着，事件不需要直接写「对哪个维度施加什么操作」，它只需要声明自己的意图类型（比如 focus_gain），系统会自动查找 effect_mapping 并执行对应的操作。这为后续的条件规则（rules、overlays）提供了统一的锚点——规则不再需要针对每个具体事件编写，而是针对意图类型统一生效。

## 四、行为链的先后执行：为什么顺序决定一切

行为链（Sequence）是 MindFlow 中最重要的结构之一。它定义了**多个事件的先后执行顺序**。

### 4.1 示例：压力偏高的修复链

```yaml
- id: seq_plan_exec__belief_repair_stress_to_relax_then_plan
  name: 【计划序列】压力偏高：先降压再规划
  type: sequence
  steps:
  - evt_request_help_3sentences      # 求助 → 情绪+4, 压力-5, 皮质醇-4, 血清素+2
  - evt_background_incubation_set    # 孵化 → 情绪+2, 压力-3, 皮质醇-4
  - evt_phase_immersive_recover      # 恢复 → 精力+8, 情绪+5, 压力-4, 皮质醇-5, 血清素+4
  - evt_scene_7_assembly_line        # 流水线 → 专注+4, 动力+3, 情绪+1
  - evt_scene_4_eat_frog             # 吞青蛙 → 专注+1, 动力+1, 情绪+1
```

这条链的设计逻辑是**阶段性的**：

1. **先降压**：求助 + 孵化 + 高沉浸恢复，把压力从高位拉下来；
2. **再赋能**：流水线 + 吞青蛙，在低压力的基础上重建专注和动力。

如果把顺序反过来——先吞青蛙再求助——效果会完全不同。因为在高压状态下，「吞青蛙」事件的 delta 虽然名义上能给专注+1、动力+1，但 overlay 规则中的「缺觉模式」或类似的「高压惩罚规则」可能会把这些增益打折到原来的 0.5 倍甚至更低。

**这就是行为链的核心算法：先后顺序改变了每次执行时的初始状态，而初始状态决定了行为效果的实际值。**

### 4.2 行为执行的数学模型（概念级）

设状态空间为向量 **S** = [情绪, 专注, 动力, 压力, 精力, 睡眠, 运动, 多巴胺, 皮质醇, 血清素]。

设行为 E_i 的基础状态变化为向量 **ΔE_i**。

设当前状态为 **S_t**，覆盖层规则集合为 **O(S_t)**，返回一组乘数修正。

则行为 E_i 在时刻 t 的实际效果为：

```
ΔE_i_actual = ΔE_i × O(S_t)
S_{t+1} = S_t + ΔE_i_actual
```

当行为链执行时：

```
S_0 = 初始状态
S_1 = S_0 + ΔE_0 × O(S_0)
S_2 = S_1 + ΔE_1 × O(S_1)
...
S_n = S_{n-1} + ΔE_{n-1} × O(S_{n-1})
```

每一步的 O(S_t) 都依赖于上一步的输出，这就是为什么**顺序不是任意的，而是因果的**。

### 4.3 目标状态驱动的路径规划

MindFlow 中还定义了**目标状态模板（target_state_templates）**，例如：

```yaml
- id: target_focus
  name: 提升专注
  type: target
  state:
    subjective:
      专注: [70, 100]     # 专注需要达到 70-100
      动力: [50, 100]     # 动力不低于 50
```

系统的理想运作方式是：给定一个初始状态（如 init_low_energy）和一个目标状态（如 target_focus），自动规划一条行为链，使得经过链中所有事件的累积效果后，状态能够落入目标区间。

这在数学上是一个**有约束的最短路径问题**：在行为库中搜索一条事件序列，使得：
- 序列长度不超过 max_steps（如 40）；
- 每一步的状态都在合法边界内（bounds）；
- 最终状态落入目标区间。

## 五、类黑盒随机性：认知隔断的物理实现

到这里，已经出现了一个结构性的问题：**行为链的顺序是由谁决定的？**

在 MindFlow 中，行为链的顺序是**设计者**在事件规划阶段（planner）决定的。设计者根据当前状态和目标状态，选择或生成一条行为序列，然后将其密封，交由执行者按顺序执行。

但如果设计者自己也不知道该选哪条链呢？

这正是骰子随机性发挥作用的时刻。

### 5.1 两种随机性的方向差异

在之前的《午休板块》文章中，我们已经区分了两种随机性：

| 类型 | 服务对象 | 功能 | 案例 |
|------|---------|------|------|
| **涌现型随机** | 设计者 | 打破设计的僵局，从死胡同中找到新入口 | 创作中扔硬币决定剧情走向 |
| **隔断型随机** | 执行者 | 保护执行的纯粹性，关掉设计者的麦克风 | 午餐骰子 |

MindFlow 中的决策树（decision_trees）结构，天然支持这两种随机性的共存。

### 5.2 决策树中的随机性机制

在 story-tree-editor 的引擎代码（engine.py）中，存在一个**安全表达式求值器（SafeExpressionEvaluator）**，它使用 Python 的 ast 模块解析和执行状态公式。这套机制允许节点的行为效果由公式动态计算，而不是写死的常量。

在这个基础上，**随机性可以以两种方式介入**：

**方式一：执行者侧的骰子**
- 行为库中有 3 条不同的恢复链（A、B、C），设计者预先封装；
- 执行者掷骰子决定今天走哪条链；
- 一旦选定，整条链的执行是密封的，不允许中途切换。

**方式二：设计者侧的条件分支**
- 决策树的节点包含 when 条件判断；
- 系统根据当前状态自动选择走哪个分支；
- 这不是随机选择，而是**条件驱动的自动化路由**。

两者的区别在于：骰子是由执行者在执行时触发的外部事件；条件分支是由系统在执行前根据状态评估自动选择的内部逻辑。

### 5.3 为什么类黑盒随机性是「有效认知隔断」

类黑盒随机性之所以能隔断认知，是因为它在以下三个维度上阻断了设计者的介入：

1. **信息维度**：执行者不知道行为库的全貌，只看到骰子给定的结果。就像午餐骰子不需要知道 12 套菜谱，只需要知道「今天吃鸡胸肉沙拉」。

2. **决策维度**：选择权被移交给一个物理的外部装置（骰子），执行者不能以任何理由质疑或更改结果。这消除了「我是不是该选另一条」的犹豫。

3. **时间维度**：掷骰子是一个不可逆的瞬间动作。你可以在掷之前犹豫，但掷出之后，骰子朝上的那一面就是确定的。这种物理确定性切断了思维的回旋空间。

在 MindFlow 的术语中，这就是**密封指令机制（sealed instruction）**在行为链层面的具体实现：设计者预先封装好行为库和映射规则，执行者通过随机量选择一个行为序列，然后密封执行，直到检查点再重新评估。

## 六、已有实现的粗糙之处与迭代方向

MindFlow 的现有实现已经搭建起了骨架，但在以下几个层面还有显著的粗糙之处：

### 6.1 行为效果是静态数字，缺少动态适应

当前，每个事件的 delta 是写死的常量。但现实中，同一个行为在不同状态下产生的效果是不同的。

- 同样的「步行补能」行为，在精力为 30 和精力为 70 时的增益应该不同；
- 同样的「求助」行为，在有可信关系和无可信关系时的效果应该不同。

**迭代方向**：引入 effect_formula（效果公式），用 SafeExpressionEvaluator 动态计算 delta，使得行为效果依赖于当前状态。

### 6.2 行为链的路径规划还停留在手动编制

当前，所有的行为链（sequences）都是人工编写的，系统没有自动搜索和规划能力。

**迭代方向**：实现基于状态空间搜索的路径规划算法，给定初始状态和目标状态，自动生成最优行为链。

### 6.3 overlay 规则的种类和优先级还不够丰富

当前只有少量的覆盖层规则（如缺觉模式），规则的优先级和冲突解决机制也还很简单。

**迭代方向**：扩展覆盖层规则库，引入规则冲突的优先级仲裁机制。

### 6.4 状态变更记录与实际状态追踪脱节

MindFlow Web 的 cycle_executor_service 中，tick_run 会记录每次执行后的 state_delta，但这个记录目前没有被反馈回行为规划系统。

**迭代方向**：建立闭环——执行记录 → 效果验证 → 行为库调参 → 下次规划，形成自我校准的系统。

### 6.5 随机性的介入还缺乏系统化的设计

当前骰子和决策分支的随机性散落在不同模块中，没有统一的「随机性配置层」。

**迭代方向**：建立一个 random_layer（随机层），统一管理骰子映射、条件分支概率、扰动幅度等参数，使随机性成为系统的一个可控维度而非临时补丁。

## 七、总结：从菜谱到心智的同一套设计模式

把午餐菜谱系统和 MindFlow 行为系统放在一起看，会发现它们共享同一套设计模式：

| 层次 | 午餐系统 | MindFlow |
|------|---------|---------|
| **预设空间** | 12 套菜谱 | 事件库（20+ 行为模板） |
| **状态指标** | 饥饿度、饱腹感、清醒度 | 情绪、专注、动力、压力、精力 |
| **选择机制** | 骰子随机 | 骰子随机 + 条件分支 |
| **执行机制** | 密封指令 → 执行 → 记录 | 密封行为链 → tick 执行 → 记录 state_delta |
| **校准机制** | 每周趋势分析 → 调参 | overlay 规则 → 条件修正 |
| **认知隔断** | 骰子切断设计者在修复环的介入 | 随机量切断设计者在行为选择中的犹豫 |

这套设计模式的核心命题是：**在一个需要反复执行但又不需要反复决策的场景中，用一个预先封装好的选择空间 + 一个随机选择机制 + 一个密封执行流程，替代执行时的临时决策。**

它不是一个效率技巧，而是一种认知治理方案——承认人在执行时的认知带宽有限，承认设计者的反思冲动会在不该出现的时候出现，然后用制度而不是意志力来解决这个问题。

MindFlow 的实现还很粗糙，但骨架是对的。下一步的关键不是把现有的行为库做得更大更全，而是把**行为效果与状态的动态关联**、**路径规划的自动化**、**随机性的系统化管理**这三件事做扎实。
