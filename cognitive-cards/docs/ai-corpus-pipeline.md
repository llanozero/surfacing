# AI 语料管线：生成 → 共鸣 → 路线 → 反馈权重

在涌现引擎（语义匹配 → 语料细化 → 锦囊涌现）的基础上，增加一条完整的 AI 驱动数据管线。与肉身边界体验的直觉路径不同，这条管线走的是第二条认知路径——通过海量数据推测、匹配、连接，以量的堆积逼近本质，再通过用户行为的反馈闭环持续调优。

## L1：AI 语料生成

### 定位

不依赖人的肉身经历来产出语料——那是第一条路径（界限体验）的领地。这里走的是第二条路径：AI 在已有数据的骨架上，批量化生成新语料条目。它不是"创作"，而是以现有高质量语料为种子，在风格、意象、句式的约束下扩展。

### 生成流程

```
现有数据骨架
  ├── cards.json    → 卡片定义（洞察 + 设计指令 + 产品形态）
  ├── corpus.json   → 已有语料（风格标签 + 关键词 + 标注）
  └── kits.json     → 锦囊骨架（触发条件 + body + 机制）
          │
          ▼
┌─────────────────────────────────────────────┐
│            AI 语料生成器                      │
│                                              │
│  系统提示词：                                  │
│  "你是一个认知语料生成器。你的任务是基于        │
│   卡片的核心洞察和设计指令，生成与现有语料       │
│   风格一致、但覆盖不同意象和场景的新语料条目。   │
│                                              │
│   约束：                                      │
│   1. 控制长度（50-150 字）                    │
│   2. 包含至少一个感官意象                      │
│   3. 避免抽象说教，用比喻和画面                │
│   4. 贴合卡片的洞察方向                       │
│   5. 生成 3 种不同风格的变体"                  │
│                                              │
│  输入：卡片 ID + 已有语料（few-shot）+ 指令    │
│  输出：候选语料条目 + 风格标签 + match_keywords │
└─────────────────────────────────────────────┘
          │
          ▼
    ┌──────────┐
    │  人工审核  │  ← 设计者把关，防止低质数据污染
    └────┬─────┘
         │ 通过
         ▼
    corpus.json 追加条目
```

### 生成类型

| 类型 | 触发条件 | 生成内容 | 用途 |
|------|----------|----------|------|
| 语料扩展 | 某卡片语料 < 3 条 | 为该卡片生成 3-5 条新语料 | 丰富匹配池 |
| 风格补全 | 某卡片缺少某种风格 | 生成指定风格的语料 | 覆盖更多用户风格 |
| 场景覆盖 | 用户反馈中出现新场景关键词 | 生成新场景的语料 | 扩大共鸣范围 |
| 锦囊变体 | 某锦囊引导词使用频率高 | 生成该锦囊的引导词变体 | 避免重复感 |

## L2：AI 认知共鸣匹配

### 定位

当前阶段一的 Jaccard 关键词匹配只是一个原型占位。真正的数据推演路径，匹配质量取决于语义理解的深度。这里用 LLM 替代关键词硬匹配，实现"共鸣级"匹配——不是看用户输入里有没有某个词，而是理解用户输入背后是**什么样的状态、处在循环的哪个位置、需要什么样的意象**。

### 共鸣匹配 vs 关键词匹配

| | 关键词匹配（当前） | 共鸣匹配（L2） |
|------|----------|----------|
| 输入处理 | 提取 2-4 字片段 | 语义向量化 + LLM 理解 |
| 匹配对象 | cards.json 的 keywords 字段 | 卡片洞察 + 语料全文本 |
| 输出 | card_id + Jaccard 分数 | card_id + 共鸣理由 + 共鸣强度 + 状态分析 |
| 例："越准备越焦虑" | 匹配到 Card 05（信心 0.02） | "用户处在设计者心态的过度准备阶段，卡在执行者入口。与合拍飞轮的'预热过渡'洞察深度共鸣，同时带有二阶观察者困境的自我审视特征。" |

### 共鸣维度

LLM 在匹配时从四个维度评估共鸣：

| 维度 | 说明 | 示例 |
|------|------|------|
| **机制共鸣** | 卡片的洞察命中了用户困境的核心机制 | "越准备越焦虑" → 合拍飞轮的预热过度 |
| **结构共鸣** | 用户的处境再现了卡片描述的自我指涉结构 | "审视自己在准备" → 二阶观察者困境 |
| **意象共鸣** | 语料的比喻或画面能与用户的情绪状态共振 | "飞轮"的意象安抚了对"开始"的恐惧 |
| **风格共鸣** | 语料的表达风格与用户的叙事方式一致 | 用户偏叙事 → 匹配诗意_温和风格语料 |

## L3：路线与分支连接

### 定位

单条语料是散的。L3 将 L2 产出的共鸣语料子集连接成叙事路线——不是一条直线到底，而是在关键节点设置分支。每条分支对应一个用户可能的状态转向，由不同的锦囊引导。

### 路线生成流程

```
L2 共鸣语料子集 (3-5条)
   + 用户状态分析
   + 锦囊骨架 (kits.json)
          │
          ▼
┌────────────────────────────────────────────┐
│  LLM 路线生成器                              │
│                                              │
│  系统提示词：                                  │
│  "你是一个认知路线设计师。给定一组共鸣语料     │
│   和锦囊骨架，你需要设计一条包含分支的认知     │
│   引导路线。                                   │
│                                              │
│   规则：                                      │
│   1. 主干路线从当前状态出发，经过 3-5 个节点   │
│   2. 每个节点 = 一条语料 + 一个锦囊            │
│   3. 在锦囊 B/C/F 位置设置分支判断点           │
│   4. 分支触发条件用可检测的用户信号描述         │

    ┌──────┴──────────┐

┌──────────┐    ┌──────────┐

     │               │

│ 锦囊 D   │    │ 锦囊 F   │  作用: 具身启动
│(自防御后) │    │(具身认知) │

```

### 分支触发信号

| 分支点 | 检测信号 | 触发条件 | 走向 |
|--------|----------|----------|------|
| B→C (负向沉沦) | 用户输入中出现更多负面词汇 | 焦虑/崩溃/不行/放弃 出现 | 进入负向沉沦旁路 |
| B→E (回归执行者) | 用户输入减少、出现接受信号 | "好像懂了" / 停顿 / 不再追问 | 进入执行者通道 |
| C→D 或 E | 用户是否停止了描述 | 沉默期 > 60s → D（自防御后），继续输入 → 停留在 C | 自防御或持续沉沦 |
| F→G (复盘) | 用户描述了完成体验 | 出现了"做完了" / "感觉" 等体验描述 | 进入设计者复盘 |

## L4：反馈权重调整

### 定位

L1-L3 是"生成 → 匹配 → 连接"的正向管线。L4 是反向的——用户的行为信号回流到系统，调整下一次推荐的权重。这是数据推演路径的闭环：**不是靠一个人在边界处试错，而是靠海量用户的行为数据持续校准**。

### 采集的信号

| 信号 | 采集方式 | 含义 | 权重影响 |
|------|----------|------|----------|
| 语料曝光 | 系统展示了某条语料 | 被看到 | +轻微 |
| 语料共鸣确认 | 用户点击"有帮助" / 做了身体动作 | 该语料命中了状态 | ++该语料 + 同风格语料 |
| 语料跳过 | 用户在语料展示后 < 3s 请求下一条 | 不匹配 | -该语料在此场景 |
| 锦囊执行确认 | 用户点击"我试了" / 返回了执行结果 | 锦囊有效 | ++该锦囊 + 同级锦囊 |
| 路线完成 | 用户走完了整条路线 | 路线有效 | +++该路线模板 |
| 路线中途退出 | 用户在中间节点停止交互 | 路线断裂 | -该路线在断裂处调整分支 |
| 路线中途跳到别处 | 用户自己搜索/重新输入 | 路线不匹配当前状态 | -该路线对当前状态 |
| 用户主动评分 | 在节点结束处邀请评分（1-5） | 直接满意度 | +++直接调整 |

### 权重计算公式

```
new_weight = old_weight × (1 - decay_rate)
           + signal_reward × learning_rate

其中：
  - decay_rate = 0.01（自然衰减，防止旧路线固化）
  - learning_rate = 0.1
  - signal_reward 由信号类型决定：

signal_reward:
  语料共鸣确认    → +0.3
  语料跳过        → -0.2
  锦囊执行        → +0.4
  路线完成        → +0.5
  路线退出        → -0.3
  主动评分 5      → +0.5
  主动评分 1      → -0.4
```

### 权重传播

某条语料获得正反馈后，不仅提升自身权重，还向相邻节点传播：

```
语料 A 获得 +0.3 共鸣反馈
          │
          ├── 语料 A:  +0.3（直接）
          ├── 同卡片语料:  +0.1（卡片关联）
          ├── 同风格语料:  +0.1（风格关联）
          ├── 同路线节点:  +0.1（路线关联）
          └── 同锦囊语料:  +0.05（锦囊关联）
```

### 冷启动 → 热数据

```
冷启动阶段                   热数据阶段
┌──────────────┐          ┌──────────────┐
│ 所有语料等权重 │   ──▶   │ 每条语料有     │
│ 路线按设计者   │  反馈   │ 场景化权重     │
│ 手工编排      │  积累   │ 路线自动趋优   │
│              │          │ 分支概率动态   │
│ 匹配靠AI理解  │          │ 匹配靠AI+历史  │
└──────────────┘          └──────────────┘
```

cognitive ai pipeline --card-id card_05   # 生成 → 匹配 → 路线 → 初始化权重

## 与涌现引擎的关系

```
┌──────────────────────────────────────────────────────┐
│                    cognitive-cards                     │
│                                                        │
│  ┌──────────────────────┐  ┌────────────────────────┐ │
│  │    涌现引擎（现有）    │  │   AI 语料管线（新增）    │ │
│  │                      │  │                        │ │
│  │  阶段一：关键词匹配    │  │  L1: AI 语料生成        │ │
│  │  阶段二：语料库细化    │  │  L2: AI 共鸣匹配 ← 替代 │ │
│  │  阶段三：锦囊路径涌现  │  │  L3: 路线与分支连接     │ │
│  │                      │  │  L4: 反馈权重调整        │ │
│  └──────────┬───────────┘  └───────────┬────────────┘ │
│             │                          │               │
│             │  匹配卡片 + 细化语料       │  共鸣语料 + 路线 │
│             └──────────┬───────────────┘               │
│                        ▼                               │
│              ┌──────────────────┐                      │
│              │   锦囊路径涌现     │  ← 两路汇合          │
│              │  LLM 生成引导词   │                      │
│              └──────────────────┘                      │
│                                                        │
│  两条输入路径 → 同一个涌现出口                           │
│  关键词路径（快、降级） + 共鸣路径（准、AI）              │
└──────────────────────────────────────────────────────┘
```

AI 语料管线不是替代涌现引擎，而是为它提供更高质量的上游数据。涌现引擎的"阶段三"锦囊生成逻辑保持不变——它只关心收到的语料质量，不关心语料来自关键词匹配还是 AI 共鸣匹配。

## 设计原则

1. **AI 生成需要人工审核**（L1）：防止低质语料污染推荐池，每一条 AI 生成的语料在入库前需要设计者确认。
2. **共鸣匹配可选降级**（L2）：LLM 不可用时自动降级到关键词匹配，保证服务不中断。
3. **路线是建议，不是强制**（L3）：路线为 AI 生成的可能性地图，用户可以在任何节点跳出、重新匹配、或手动选择锦囊。
4. **权重数据透明可查**（L4）：所有语料和路线的权重变化记录完整历史日志，支持设计者回溯和手动干预。
5. **反馈闭环不替代设计者判断**：权重调整自动运行，但设计者保留"锁定"某条路线的能力，被锁定的路线不受权重衰减影响。
