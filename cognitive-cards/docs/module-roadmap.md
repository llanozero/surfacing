# 代理人插件模块路线图

## 框架：六时段个人操作系统

将插件的功能模块按「六时段」框架分类，每个时段对应一个子目录，聚焦不同的使用场景与价值目标。

```
plugins/astrbot_plugin_proxy_agent/
├── night_rest/          # 夜晚 — 修养生息
├── morning_plan/        # 清晨 — 规划锚点
├── morning_focus/       # 上午 — 深度工作
├── noon_repair/         # 中午 — 修复缓冲
├── afternoon_collab/    # 下午 — 协作互动  ← 当前已有功能
└── evening_invest/      # 晚上 — 投资延展
```

---

## 各时段模块需求

---

### 1. `night_rest/` — 睡眠的夜晚（修养生息，能量回充）

**核心目标**：在夜间自动完成数据归档、状态清理、次日准备，让系统在用户休息时保持有序运转。

#### 需求

**1.1 会话日报归档**
- 每天固定时间（可配置，默认 23:00）自动汇总当天所有已关闭的 ProxySession
- 生成日报文本：会话数量、总消息数、活跃用户、投票结果摘要
- 通过私聊发送给管理员，并持久化到 `daily_report_{date}.json`

**1.2 过期数据清理**
- 定期清理超过 N 天（可配置，默认 30 天）的历史投票记录（`vote_history.json`）
- 清理超过阈值的会话频次记录中的低频条目（频次 = 1 且超过 60 天未更新）
- 清理前记录 warning 日志，清理后记录 info 日志

**1.3 次日任务预热**
- 管理员可通过 `/明日备注 <内容>` 指令写入次日提醒
- 次日清晨触发时段（见 `morning_plan`）自动读取并推送

---

### 2. `morning_plan/` — 规划的清晨（清晰目标，布局未来）

**核心目标**：为管理员提供每日启动仪式，明确当天的代理任务优先级和关注对象。

#### 需求

**2.1 晨间推送**
- 每天固定时间（可配置，默认 07:30）向管理员推送晨间摘要
- 内容包含：当前活跃会话列表（按频次排序）、昨日未处理消息数、待采纳投票数、`/明日备注` 内容

**2.2 优先级标记**
- 管理员可通过 `/标记优先 <会话ID>` 将某个 ProxySession 标记为「今日优先」
- `/admin_list` 中优先会话置顶显示，标注 ⭐ 标记
- 优先标记在会话关闭后自动清除

**2.3 每日目标设定**
- 管理员可通过 `/今日目标 <内容>` 设定当天的核心目标（纯文本备忘）
- 目标持久化到 `daily_goals.json`，晨间推送时一并展示
- `/查看目标` 随时查看当天目标

---

### 3. `morning_focus/` — 专注的上午（深度工作，技能精进）

**核心目标**：为用户提供「免打扰」保护机制，在深度工作时段自动过滤低优先级的代理消息干扰。

#### 需求

**3.1 专注模式**
- 管理员可通过 `/专注 [分钟数]` 开启专注模式（默认 90 分钟）
- 专注模式期间：所有新 ProxySession 的消息转发到管理员时附加「[专注中，稍后回复]」标注
- 专注模式期间：非优先会话的消息进入「缓冲队列」，不立即推送，专注结束后批量摘要推送
- 优先会话（见 `morning_plan` 2.2）不受专注模式影响，仍实时推送

**3.2 专注统计**
- 记录每次专注的开始时间、结束时间、期间缓冲的消息数
- 持久化到 `focus_log.json`
- `/专注统计` 查看近 7 天的专注记录

**3.3 缓冲队列摘要**
- 专注结束后，自动向管理员推送缓冲期间积压的消息摘要
- 格式：`[会话ID] 用户X 发送了 N 条消息，最新内容：<最后一条消息前50字>`
- 管理员可通过 `/查看缓冲` 随时查看当前缓冲队列

---

### 4. `noon_repair/` — 修复的中午（放松身心，缓冲压力）

**核心目标**：午休时段的轻量化管理，自动处理简单的重复性任务，减少管理员的认知负担。

#### 需求

**4.1 自动回复模板**
- 管理员可配置午休自动回复模板（如「正在午休，稍后回复」）
- 通过 `/午休 [分钟数]` 开启，期间新消息自动回复模板内容给发起者
- 不影响消息的正常转发记录，管理员午休结束后仍可查看完整消息

**4.2 快捷回复**
- 管理员可预设最多 10 条快捷回复短语（`/设置快捷回复 <编号> <内容>`）
- 通过 `/快捷 <编号> <会话ID>` 快速回复，减少重复输入
- `/查看快捷回复` 列出所有预设短语

**4.3 消息合并推送**
- 可配置「合并推送间隔」（默认 0，即实时推送）
- 设置后，同一会话在间隔时间内的多条消息合并为一条推送给管理员
- 合并格式：`[N条消息] 内容1 / 内容2 / ...`

---

### 5. `afternoon_collab/` — 协作的下午（外部互动、关系维护、思维推进）

**核心目标**：已有功能的持续完善，强化多人协作与思维外化场景。

> 当前已有：代理转发、交互式选择、群聊投票、会话列表、频次统计、长消息渲染

#### 待补充需求

**5.1 消息标注与追踪**
- 管理员可对某条转发消息添加标注（`/标注 <会话ID> <备注>`）
- 标注内容在 `/admin_list` 详情中展示
- 支持按标注关键词搜索会话（`/搜索会话 <关键词>`）

**5.2 多管理员支持**
- 支持配置多个管理员 ID（`admin_ids` 列表）
- 消息转发给所有管理员，任意管理员均可回复
- 记录是哪位管理员回复的，在会话日志中标注

---

### 6. `evening_invest/` — 投资的晚上（兴趣发展，深度链接）

**核心目标**：利用白天互动产生的新思路，进行深度整理与关系投资，构建个人知识资产。

#### 需求

**6.1 会话洞察报告**
- 管理员可通过 `/洞察 <会话ID>` 生成某个 ProxySession 的深度分析报告
- 报告内容：消息时间线、高频词汇、情感倾向（正面/中性/负面关键词统计）、互动节奏
- 报告以长消息图片形式发送（走 `_send_auto` 流程）

**6.2 关系图谱**
- 基于 `session_frequency.json` 数据，生成用户关系热度图
- `/关系图谱` 指令输出文本版热度排行（Top 10 高频用户对）
- 数据可导出为 JSON 供外部工具使用（`/导出关系数据`）

**6.3 深度对话模式**
- 管理员可为某个 ProxySession 开启「深度对话模式」（`/深度 <会话ID>`）
- 开启后：转发给管理员的消息附加「上下文摘要」（最近 5 条消息的简要回顾）
- 帮助管理员在晚间回顾时快速进入对话语境，无需翻阅历史记录

**6.4 每日复盘**
- 管理员可通过 `/复盘` 触发当天的互动复盘
- 内容：今日目标完成情况、会话活跃度、投票结果、专注时长、关键互动摘要
- 结合 `morning_plan` 的今日目标，对比实际完成情况

## 配置项规划

| 配置键 | 类型 | 默认值 | 所属时段 | 说明 |
|--------|------|--------|----------|------|
| `daily_report_time` | string | `"23:00"` | night_rest | 日报发送时间 |
| `data_retention_days` | int | `30` | night_rest | 历史数据保留天数 |
| `morning_push_time` | string | `"07:30"` | morning_plan | 晨间推送时间 |
| `focus_default_minutes` | int | `90` | morning_focus | 默认专注时长 |
| `merge_push_interval` | int | `0` | noon_repair | 消息合并推送间隔（秒），0 为禁用 |
| `noon_auto_reply` | string | `""` | noon_repair | 午休自动回复模板，空为禁用 |
| `admin_ids` | list | `[]` | afternoon_collab | 多管理员 ID 列表 |

---

## 实现优先级建议

```
P0（当前）：afternoon_collab — 已有，持续完善
P1（近期）：morning_plan + noon_repair — 轻量，高频使用
P2（中期）：morning_focus + night_rest — 自动化，需定时任务
P3（远期）：evening_invest — 数据分析，依赖前期数据积累
```
