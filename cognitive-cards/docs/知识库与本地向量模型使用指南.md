## 1. 知识库整体架构

AstrBot 的知识库系统位于 `core/knowledge_base/`，由四个核心子系统组成管道式架构：

```
文档上传 → Parsers(解析) → Chunking(分块) → Embedding(向量化) → VecDB(存储) → Retrieval(检索)
```

## 2. 管道四阶段详解

### 2.1 解析阶段（Parsers）

**文件**：`core/knowledge_base/parsers/`

| 解析器 | 处理格式 |
|--------|----------|
| `TextParser` | `.txt`、`.md`、`.py` 等纯文本 |
| `PDFParser` | `.pdf` |
| `MarkitdownParser` | `.docx`、`.xlsx`、`.pptx` 等 Office 文档 |
| `URLExtractor` | HTTP URL（网页抓取） |

`util.py` 中的 `select_parser(file_path)` 根据文件扩展名自动选择对应的解析器，返回解析后的 `ParsedDocument`（包含文本内容和元数据）。

### 2.2 分块阶段（Chunking）

**文件**：`core/knowledge_base/chunking/`

主要使用 `RecursiveCharacterChunker`（递归字符分块器）：

- 按段落、句子等自然边界递归切分
- `chunk_size` 和 `chunk_overlap` 可配置
- 也提供 `FixedSizeChunker`（固定大小分块）作为备选

分块器继承自 `BaseChunker` 抽象基类。

### 2.3 嵌入/向量化阶段（Embedding）

**文件**：`core/knowledge_base/kb_helper.py` + `core/provider/`

`KBHelper` 调用 `EmbeddingProvider` 将每个文本块转为向量：

```python
# 核心调用链
KBHelper → ProviderManager → EmbeddingProvider.get_embeddings(texts) → 返回向量列表
```

**支持的嵌入模型 Provider**：

| Provider | 文件 | 说明 |
|----------|------|------|
| `OpenAIEmbeddingProvider` | `openai_embedding_source.py` | OpenAI 及兼容 API（**最关键，支持本地 LM**） |
| `GeminiEmbeddingProvider` | `gemini_embedding_source.py` | Google Gemini 嵌入 API |

### 2.4 检索阶段（Retrieval）

**文件**：`core/knowledge_base/retrieval/`

`RetrievalManager` 协调**三路检索 + 融合**：

1. **稠密检索**（Dense）：通过 `FaissVecDB` 的 FAISS 索引做向量相似度搜索
2. **稀疏检索**（Sparse）：通过 `SparseRetriever`（基于 SQLite FTS5 全文索引的 BM25 关键词检索）
3. **重排序**（Rerank）：通过 `RerankProvider` 对候选结果精排
4. **融合**：`RankFusion` 将稠密和稀疏结果做加权融合

最终返回 `RetrievalResult` 列表供 LLM 上下文注入。

## 3. 向量数据库实现（FAISS）

### 3.1 FAISS 架构

`FaissVecDB`（`core/db/vec_db/faiss_impl/vec_db.py`）实现 `BaseVecDB` 接口，使用 FAISS 做向量索引：

- **向量存储**：`EmbeddingStorage` 将 numpy 向量数组持久化为 `.npy` 文件
- **文档存储**：`DocumentStorage` 将文档元数据存入 SQLite，同时建 FTS5 全文索引（用于稀疏检索的 `to_fts5_search_text`）
- **检索流程**：
  1. 将查询文本通过 `EmbeddingProvider` 转为向量
  2. FAISS 索引执行 L2/IP 相似度搜索
  3. 返回 Top-K `Result`（含文档 ID、分数、元数据）

### 3.2 关键数据结构

```python
# core/db/vec_db/base.py
@dataclass
class Result:
    id: str          # 文档 ID
    score: float     # 相似度分数
    metadata: dict   # 附加元数据
    text: str        # 文档原文

class BaseVecDB(ABC):
    """向量数据库抽象基类"""
    async def add_documents(self, documents, embeddings): ...
    async def search(self, query_embedding, top_k, filter): ...
    async def delete(self, doc_ids): ...
    async def count(self): ...
```

## 4. 如何使用本地 LM 的向量模型

这是核心问题。AstrBot 通过 **OpenAI 兼容 API** 连接本地 LM 的嵌入模型。

### 4.1 原理

`OpenAIEmbeddingProvider`（`core/provider/sources/openai_embedding_source.py`）使用 `openai.AsyncOpenAI` 客户端调用 `/v1/embeddings` 端点。只要你的本地 LM 服务（如 LM Studio、Ollama、vLLM、Xinference 等）暴露了 OpenAI 兼容的 `/v1/embeddings` 接口，就可以作为 AstrBot 的嵌入模型使用。

### 4.2 在 AstrBot 中配置本地嵌入模型

在 AstrBot 的 Provider 配置中添加一个 Embedding Provider：

```yaml
# AstrBot 配置中的 Provider 定义（示意）
providers:
  - id: local_embedding
    name: LM Studio Embedding
    type: embedding           # ProviderType.EMBEDDING
    source: openai_embedding  # 使用 OpenAIEmbeddingProvider
    config:
      api_base: http://localhost:1234/v1   # LM Studio 本地地址
      api_key: lm-studio                    # LM Studio 默认 key
      model: text-embedding-nomic-embed-text-v1.5  # 你的嵌入模型名
```

### 4.3 关键配置参数

| 参数 | 说明 | 示例 |
|------|------|------|
| `api_base` | 本地 LM 服务的 OpenAI 兼容端点 | `http://localhost:1234/v1`（LM Studio）<br>`http://localhost:11434/v1`（Ollama）<br>`http://localhost:9997/v1`（Xinference） |
| `api_key` | API 密钥（本地服务通常任意值即可） | `lm-studio`、`not-needed` |
| `model` | 嵌入模型名称 | `text-embedding-nomic-embed-text-v1.5`、`bge-large-zh-v1.5`、`all-MiniLM-L6-v2` |

### 4.4 LM Studio 示例

1. 在 LM Studio 中加载一个嵌入模型（如 `nomic-embed-text-v1.5`）
2. 启动本地推理服务器（默认端口 1234）
3. 验证端点可用：`curl http://localhost:1234/v1/embeddings -d '{"model":"text-embedding-nomic-embed-text-v1.5","input":"hello"}'`
4. 在 AstrBot 中按上述配置填入

### 4.5 Ollama 示例

1. 拉取嵌入模型：`ollama pull nomic-embed-text`
2. Ollama 默认端口 11434，OpenAI 兼容端点在 `/v1`
3. 配置 `api_base: http://localhost:11434/v1`

### 4.6 嵌入模型推荐

| 模型 | 维度 | 适用场景 |
|------|------|----------|
| `nomic-embed-text-v1.5` | 768 | 中英文通用，性能均衡 |
| `bge-large-zh-v1.5` | 1024 | 中文最佳 |
| `bge-m3` | 1024 | 多语言，支持稠密+稀疏 |
| `all-MiniLM-L6-v2` | 384 | 轻量级，快速 |

### 4.7 验证嵌入是否正常工作

启动 AstrBot 后，上传一个文档到知识库，观察日志：

```
[INFO] 知识库: 开始处理文档 xxx.pdf
[INFO] 知识库: 解析完成，共 N 个字符
[INFO] 知识库: 分块完成，共 M 个 chunk
[INFO] 知识库: 开始向量化，使用模型 text-embedding-nomic-embed-text-v1.5
[INFO] 知识库: 向量化完成，耗时 X 秒
[INFO] 知识库: 存储到向量数据库完成
```

如果向量化阶段报错（如连接拒绝、模型不存在），说明 Provider 配置有问题。

## 5. 知识库与 Agent 的集成

`KnowledgeBaseQueryTool`（`core/tools/knowledge_base_tools.py`）将知识库封装为 Agent 可调用的工具：

- Agent 在需要外部知识时，自动调用该工具
- 工具内部执行：解析查询 → 向量化查询 → 混合检索 → 返回上下文
- 返回的上下文被注入到 LLM 的 system prompt 或消息历史中

核心函数：

```python
# 检索知识库上下文
async def retrieve_knowledge_base(
    query: str,          # 用户问题
    top_k: int = 5,      # 返回结果数
    kb_names: list = None  # 指定知识库名称（None=所有）
) -> str:
    """返回格式化后的知识库检索结果字符串"""
```

## 8. 排查清单

| 问题 | 检查点 |
|------|--------|
| 文档上传后检索不到 | 检查 Embedding Provider 是否配置正确，向量化是否成功 |
| 检索结果不相关 | 调整 chunk_size/chunk_overlap，尝试不同的嵌入模型 |
| 本地 LM 连接失败 | 确认 LM Studio/Ollama 服务已启动，端口正确，API base 地址可访问 |
| 向量化很慢 | 本地 CPU 推理较慢，考虑减小 chunk_size 或使用更轻量的嵌入模型 |
| 知识库为空 | 检查 `KnowledgeBaseManager` 初始化日志，确认知识库路径和数据目录存在 |
