# 认知卡片数据模型设计

## 概述

认知卡片系统由两个核心维度构成：

1. **语料库**（Corpus）— 每张卡片关联一个主题语料库，存储同类主题的优质文笔
2. **层级结构**（Hierarchy）— 卡片之间可以形成父子嵌套关系，子卡片继承父卡片的语料库上下文

---

## 1. 卡片数据模型

### 1.1 核心结构

```json
{
  "card": {
    "id": "card_001",
    "type": "cognitive_card",
    "number": "01",
    "title": "二阶观察者困境",
    "slug": "second-order-observer-dilemma",

    "sections": {
      "insight": "当你同时是系统的设计者与使用者，元认知的审视目光会破坏执行的纯粹性。",
      "design_directive": "将设计态与执行态物理分离。工具必须拥有两种不可混淆的模式。",
      "product_form": "双模式架构：设计模式下可编辑，执行模式下只读、不可修改。"
    },

    "tags": ["元认知", "自我指涉", "设计哲学"],
    "keywords": ["二阶观察者", "设计者心态", "执行者心态", "模式切换"],

    "parent_id": null,
    "child_ids": ["card_001_a", "card_001_b"],
    "sibling_order": 0,

    "corpus": { /* 见 2. 语料库 */ },

    "metadata": {
      "created_at": "2026-07-22T00:00:00Z",
      "updated_at": "2026-07-22T00:00:00Z",
      "version": 1,
      "status": "active"
    }
  }
}
```

### 1.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识符，格式 `card_{三位编号}` |
| `number` | string | 对外展示的卡片编号 |
| `title` | string | 卡片标题 |
| `slug` | string | URL/文件路径友好的英文标识 |
| `sections` | object | 卡片的三段式内容（insight / design_directive / product_form） |
| `tags` | string[] | 标签，用于跨卡片检索 |
| `keywords` | string[] | 关键词，用于语料库匹配和检索 |
| `parent_id` | string\|null | 父卡片 ID，`null` 表示顶层卡片 |
| `child_ids` | string[] | 子卡片 ID 列表 |
| `sibling_order` | int | 同级卡片中的排序序号 |
| `corpus` | object | 语料库数据 |
| `metadata` | object | 版本、状态、时间戳等元数据 |

## 2. 语料库（Corpus）

### 2.1 设计理念

每张认知卡片都有一个**主题语料库**，存储与卡片主题相关的优质文笔、经典论述、范例段落。

语料库的定位：
- **不是文档库** — 每条语料是精炼的片段，而非完整文章
- **不是引用库** — 语料是"如何写"的示范，而非"说了什么"的出处
- **是风格参照** — 当需要表达卡片主题时，语料库提供文笔、句式、意象的参考

### 2.2 单条语料结构

```json
{
  "corpus_entry": {
    "id": "corpus_001_001",
    "card_id": "card_001",
    "type": "excerpt",

    "source": {
      "title": "《哥德尔、埃舍尔、巴赫》",
      "author": "Douglas Hofstadter",
      "type": "book",
      "url": "",
      "year": 1979
    },

    "content": "一个系统无法在自身内部证明自身的完备性和一致性。任何足够强大的形式系统，其一致性命题都必须在系统外部才能证明。",

    "annotation": "关于自我指涉系统之局限的经典论述，语言简洁、意象清晰，可作为二阶观察者困境的类比引入。",

    "style_tags": ["学术", "清晰", "类比"],
    "relation_tags": ["self_reference", "incompleteness", "system_boundary"],
    "match_keywords": ["自我指涉", "不完备", "系统边界"],

    "quality_score": 4.5,
    "metadata": {
      "added_at": "2026-07-22T00:00:00Z",
      "added_by": "designer",
      "usage_count": 3,
      "last_used_at": "2026-07-22T00:00:00Z"
    }
  }
}
```

### 2.3 语料条目字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 语料条目 ID，格式 `corpus_{卡片ID}_{序号}` |
| `card_id` | string | 所属卡片 ID |
| `type` | string | 语料类型：`excerpt`（摘录）\| `paraphrase`（改写）\| `original`（自创）\| `reference`（引用）|
| `source` | object | 来源信息（标题、作者、类型、链接、年份） |
| `content` | string | 语料正文 |
| `annotation` | string | 设计者批注——为什么这条语料有价值，适合什么场景 |
| `style_tags` | string[] | 风格标签，如 `学术` `诗意` `简洁` `犀利` `温暖` |
| `relation_tags` | string[] | 关联主题标签，用于跨卡片语料库检索 |
| `match_keywords` | string[] | 匹配关键词，当用户输入含这些词时优先推荐此条 |
| `quality_score` | float | 质量评分（0-5），由设计者在添加时评定 |
| `metadata` | object | 添加时间、使用次数等元数据 |

### 2.4 语料类型

| 类型 | 说明 | 示例来源 |
|------|------|----------|
| `excerpt` | 外部摘录，保持原文 | 书籍、论文、演讲 |
| `paraphrase` | 改写/翻译后的版本 | 对 excerpt 做中文化或情境化改写 |
| `original` | 设计者原创 | 产品文案、使用引导 |
| `reference` | 参考链接/资源定位 | 博客 URL、论文 DOI |

### 2.5 语料库在卡片中的完整表达

```json
{
  "card": {
    "id": "card_01",
    "title": "二阶观察者困境",
    "corpus": {
      "enabled": true,
      "default_style": "清晰_克制",
      "entries": [
        {
          "id": "corpus_01_001",
          "type": "excerpt",
          "source": { "title": "Gödel, Escher, Bach", "author": "Hofstadter" },
          "content": "一个系统无法在自身内部证明自身的完备性和一致性。",
          "annotation": "自我指涉系统局限的经典论述",
          "style_tags": ["学术", "清晰"],
          "match_keywords": ["不完备", "自我指涉", "系统"]
        }
      ]
    }
  }
}
```

## 3. 卡片层级结构

### 3.1 层级设计原则

- **每个卡片可以有零个或多个子卡片**
- **子卡片继承父卡片的语料库**（继承的语料可以用，但不能删除）
- **子卡片可以覆盖父卡片的语料**（同名关键词的 entry 优先用子卡片的）
- **层级深度不限**，但建议不超过 4 层

### 3.2 示例：认知卡片的层级树

```
认知卡片 根目录
├── Card 01: 二阶观察者困境
│   ├── Card 01-a: 设计者心态详解

│   └── Card 01-b: 执行者心态训练
├── Card 02: 悖论绕过
├── Card 03: 环境级工具
│   ├── Card 03-a: 五层环境系统参考实现
│   └── Card 03-b: 感官锚点设计模式库
├── Card 04: 容器非模具
├── Card 05: 合拍飞轮
│   ├── Card 05-a: 预热过渡环节模板
│   └── Card 05-b: 节奏锚点设计
├── Card 06: 直觉即压缩理性
├── Card 07: 具身认知
│   ├── Card 07-a: 情境触发器清单
│   └── Card 07-b: 处境设计模式
├── Card 08: 自发命名
│   └── Card 08-a: 强制延迟规则配置
├── Card 09: 信念覆盖机制
```

### 3.4 继承机制

子卡片在运行时合并父卡片的语料库，继承规则：

```json
{
  "inheritance_rules": {
    "corpus_merge": {
      "strategy": "union_with_override",
      "rules": [
        "子卡片的语料条目全量保留",
        "父卡片的语料条目按关键词 merge 到子卡片",
        "关键词冲突时，子卡片的条目覆盖父卡片的",
        "父卡片语料的 style_tags 继承到子卡片，作为备选风格"
      ]
    },
    "tag_merge": {
      "strategy": "inherit_upward",
      "rules": [
        "子卡片的 tags 自动包含父卡片的所有 tags",
        "子卡片新增的 tags 不反向影响父卡片"
      ]
    },
    "section_inheritance": {
      "strategy": "none",
      "rules": [
        "sections（insight / design_directive / product_form）不继承",
        "子卡片必须独立定义自己的 sections"
      ]
    }
  }
}
```

## 4. 存储方案

### 4.1 建议的文件结构

```
cognitive-cards/
├── cards/                          # 卡片数据目录
│   ├── index.json                  # 卡片索引（含层级关系）
│   ├── card_01.json                # 单张卡片完整数据
│   ├── card_01_a.json
│   ├── card_01_a_i.json
│   ├── card_02.json
│   └── ...
├── corpus/                         # 语料库数据目录
│   ├── corpus_card_01.json         # 按卡片分隔的语料条目
│   ├── corpus_card_01_a.json
│   ├── corpus_card_02.json
│   └── ...
└── cognitive-cards.html            # 现有的展示页面
```

### 4.2 索引文件格式

```json
{
  "version": "1.0",
  "last_updated": "2026-07-22T00:00:00Z",
  "card_count": 10,
  "hierarchy": {
    "root": ["card_01", "card_02", "card_03"],
    "card_01": {
      "title": "二阶观察者困境",
      "number": "01",
      "children": ["card_01_a", "card_01_b"]
    }
  },
  "flat_list": [
    { "id": "card_01", "title": "二阶观察者困境", "parent": null },
    { "id": "card_01_a", "title": "设计者心态详解", "parent": "card_01" }
  ]
}
```

### 4.3 查询示例

```javascript
// 获取某个卡片及其所有子卡片的完整语料库
async function getCardCorpusWithInheritance(cardId) {
  const card = await loadCard(cardId);
  let corpus = [...card.corpus.entries];

  // 递归获取父卡片的语料
  if (card.parent_id) {
    const parentCorpus = await getCardCorpusWithInheritance(card.parent_id);

    // 合并规则：子卡片关键词覆盖父卡片
    const childKeywords = new Set(corpus.map(e => e.match_keywords).flat());
    const filteredParent = parentCorpus.filter(
      entry => !entry.match_keywords.some(kw => childKeywords.has(kw))
    );

    corpus = [...filteredParent, ...corpus];
  }

  return corpus;
}

// 按 style 标签检索语料
function filterCorpusByStyle(corpus, styleTag) {
  return corpus.filter(entry => entry.style_tags.includes(styleTag));
}

// 按关键词匹配推荐语料
function matchCorpusByKeywords(corpus, keywords) {
  return corpus
    .map(entry => ({
      entry,
      score: entry.match_keywords.filter(kw => keywords.includes(kw)).length
    }))
    .filter(item => item.score > 0)
    .sort((a, b) => b.score - a.score)
    .map(item => item.entry);
}
```

## 5. 两种模式中的使用方式

### 5.1 设计模式（设计者心态）

| 操作 | 说明 |
|------|------|
| 添加语料 | 向卡片的 corpus.entries 中添加新条目 |
| 编辑层级 | 创建子卡片、移动卡片在层级中的位置 |
| 评分语料 | 调整 quality_score，汰换低分条目 |
| 标注风格 | 为语料打 style_tags，丰富检索维度 |
| 配置继承 | 调整子卡片的 corpus_merge 策略 |

### 5.2 执行模式（执行者心态）

| 操作 | 说明 |
|------|------|
| 读取语料 | 只读访问当前卡片 + 继承的语料库 |
| 检索推荐 | 按关键词自动匹配最相关的语料条目 |
| 风格切换 | 在继承的 style_tags 中选择当前写作风格 |
| 使用计数 | 自动记录 usage_count，辅助设计者做汰换决策 |

### 5.3 锦囊联动

锦囊妙计在运行时根据当前卡片关联的语料库，提取最匹配的优质文笔作为引导词的参考风格：

```
当前卡片: Card 03 "环境级工具"
当前锦囊: 锦囊B "迷失预警"
匹配风格: "温暖_克制" 的语料优先
→ 引导词的写作风格从该语料库中采样
```
