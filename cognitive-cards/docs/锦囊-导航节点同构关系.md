# 锦囊-导航节点同构关系

## 概述

锦囊（Kit）与导航节点（NavNode）构成**同构关系**——两者共享相同的数据结构骨架和图论语义，可共存于同一导航图谱中参与浏览、规划、搜索等所有操作。

该同构设计使得锦囊不再是孤立定义的"引导词模板"，而是导航网络中的一等公民，可以与认知卡片、导航节点自由连接，形成统一的涌现路径网络。

---

## 1. 同构定义

### 1.1 数据模型对比

| 维度 | 导航节点 (NavNode) | 锦囊 (Kit) | 同构推论 |
|------|-------------------|------------|----------|
| 标识 | `id` | `id`（如 `kit_b`） | 统一 GraphNode.id |
| 显示名 | `label` | `name`（如"迷失预警"） | 统一 label 字段 |
| 描述 | `description` | `mechanism`（机制说明） | 统一 description 字段 |
| 出向连接 | `next_nodes[]`（`{target_id, preset_priority, ...}`） | `next_kits[]`（`kit_b → kit_c`） | 统一 next 边列表 |
| 绑定卡片 | `bound_cards[]` | 通过 `trigger` 字段隐式关联 | 统一 bound_cards[] |
| 优先级 | `priority_config.preset_priority` | 路径规则中隐含优先级 | 统一优先级序号系统 |
| 浏览记录 | `browse_history[]` | 无（新增） | 统一浏览记录追踪 |

### 1.2 统一数据模型 (GraphNode)

```typescript
/** 导航图谱中的通用节点——锦囊与导航节点共用此结构 */
export interface GraphNode {
  /** 节点标识，如 'node-ml-foundation' 或 'kit_b' */
  id: string

  /** 节点类型，区分来源 */
  node_type: 'nav_node' | 'kit'

  /** 显示标签 */
  label: string

  /** 描述/机制说明 */
  description: string

  /** 绑定的认知卡片 ID 列表 */
  bound_cards: string[]

  /** 出向连接（优先序号列表，数字越小越优先） */
  next: {
    target_id: string
    preset_priority: number
    connection_type: 'preset' | 'browse_derived' | 'user_added'
  }[]

  /** 浏览跳转历史 */
  browse_history: {
    from: string
    count: number
    last_at: string
  }[]

  /** 锦囊专属字段（kit 类型有效） */
  kit_specific?: {
    /** 锦囊字母编号（A-H） */
    letter: string
    /** 触发条件描述 */
    trigger: string
    /** 引导词正文 */
    body: string[]
    /** 视觉主题色 */
    color: string
    /** 在认知循环中的位置 */
    cycle_position: string
  }

  /** 导航节点专属字段（nav_node 类型有效） */
  nav_specific?: {
    /** 优先级配置 */
    priority_config: {
      mode: 'mixed' | 'user_only'
      preset_priority: number
      browse_priority: number
      user_overrides: { target_id: string; override_weight: number }[]
    }
    /** 原始标签（未归一化） */
    raw_label?: string
  }
}
```

### 1.3 标识命名空间

为避免 ID 冲突，锦囊与导航节点使用不同的 ID 前缀：

```
导航节点: node-{slug}        如 node-ml-foundation, node-linear-algebra
锦囊:      kit_{字母}         如 kit_a, kit_b, kit_h
```

两者在同一图谱中通过 `node_type` 字段区分，ID 本身不强制带前缀但建议遵循命名惯例。

## 2. 同构带来的统一操作

### 2.1 导航图谱

锦囊节点自动出现在导航图谱中，与导航节点共享画布：

```
导航图谱示例：

  [node-A] ──→ [node-B] ──→ [node-C]
      │                          │
      ▼                          ▼
  [kit_b] ──→ [kit_e] ──→ [kit_f] ──→ [kit_g] ──→ [kit_a]
                                               │
                                               ▼
                                          [node-D]
```

- 锦囊之间的连接取自 `kits.json` 中每个 kit 的 `next_kits` 列表
- 锦囊与导航节点之间可通过快捷连接手动建立边
- 全览视图渲染时，锦囊节点使用其 `kit_specific.color` 作为节点颜色

### 2.2 路线规划

途经点可混合包含导航节点和锦囊：

```
途经点：[node-A, kit_b, node-C]
  │
  ▼
规划结果：
  方案1（推荐）：node-A → kit_b → node-C  (总权重 2.45)
  方案2：         node-A → node-C → kit_b  (总权重 1.82)
```

规划算法处理混合节点的规则：
- 导航节点之间的出向连接：按 `next_nodes` 中的优先级 + 浏览历史计算
- 锦囊之间的出向连接：按 `next_kits` 的顺序计算（next_kits 的顺序即优先级）
- 跨类型连接（导航节点→锦囊、锦囊→导航节点）：仅当手动建立连接后纳入计算

### 2.3 浏览流程

浏览模式不区分节点类型，统一按规划序列推进：

```
当前序列：[node-A → kit_b → kit_e → node-B]
                  ↓         ↓         ↓
  step 1:   浏览 node-A 绑定的认知卡片
  step 2:   展示 kit_b 的引导词（body）
  step 3:   展示 kit_e 的引导词（body）
  step 4:   浏览 node-B 绑定的认知卡片
```

- 当当前节点类型为 `nav_node`：展示绑定的认知卡片（与现有浏览行为一致）
- 当当前节点类型为 `kit`：展示锦囊的引导词内容（`body` 数组），而非认知卡片

### 2.4 搜索

搜索同时索引导航节点和锦囊的字段：

| 搜索类型 | 导航节点匹配字段 | 锦囊匹配字段 |
|----------|-----------------|-------------|
| 关键词 | label, description | name, trigger, mechanism |
| 向量（语料库） | bound_cards 下的语料 | 关联卡片的语料 |

搜索结果的 `node_type` 字段供前端区分渲染样式。

### 2.5 视图切换

视图切换不需要区分节点类型，锦囊节点在以下视图中均有呈现：

| 视图 | 锦囊的呈现方式 |
|------|---------------|
| 导航 (nav) | 全览/逐站图中作为节点显示，颜色取自 `kit_specific.color` |
| 规划 (plan) | 可参与途经点选择和路线排序 |
| 浏览 (browse) | 当序列包含锦囊时展示引导词正文 |
| 树形管理 (tree) | 锦囊列表作为独立子树显示 |

## 3. 数据存储

### 3.1 kits.json 扩展

保留现有 `kits.json` 结构，新增 `next_nodes` 字段以支持跨类型连接：

```json
{
  "version": "2.0",
  "kits": [
    {
      "id": "kit_b",
      "letter": "B",
      "name": "迷失预警",
      "trigger": "状态正在流转——注意力涣散、方向感弱化",
      "body": ["..."],
      "mechanism": "...",
      "color": "accent2",
      "cycle_position": "迷失预警",
      "next_kits": ["kit_c", "kit_e"],
      "next_nodes": ["node-mindfulness-entry"],
      "bound_cards": ["card_05", "card_10"]
    }
  ],
  "path_rules": { "...": "..." }
}
```

新增字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| `next_nodes` | string[] | 锦囊可跳转到的导航节点 ID 列表（跨类型连接） |
| `bound_cards` | string[] | 该锦囊关联的认知卡片 ID 列表（原通过 trigger 隐式关联，现显式声明） |

### 3.2 导入 data.yaml

在 YAML 导入/导出中，锦囊数据作为 `navigation_nodes` 的一部分导出（`node_type: kit`）：

```yaml
cognitive_cards:
  - id: card_01
    title: "二阶观察者困境"
    # ...

navigation_nodes:
  - id: node-ml-foundation
    node_type: nav_node
    label: "机器学习基础"
    # ...

  - id: kit_b
    node_type: kit
    label: "迷失预警"
    description: "迷失是节律的暂时断裂..."
    next:
      - target_id: kit_c
        preset_priority: 1
        connection_type: preset
      - target_id: kit_e
        preset_priority: 2
        connection_type: preset
    kit_specific:
      letter: B
      trigger: "状态正在流转..."
      body: ["..."]
      color: accent2
      cycle_position: "迷失预警"
```

## 4. 后端 API 扩展

### 4.1 统一图查询

```
GET /api/graph/nodes
```

返回混合列表（导航节点 + 锦囊），每个节点带 `node_type` 字段。

```
GET /api/graph/edges
```

返回所有有向边，包括：
- 导航节点 → 导航节点
- 导航节点 → 锦囊
- 锦囊 → 锦囊
- 锦囊 → 导航节点

### 4.2 锦囊专用端点（新增）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/kits` | 获取所有锦囊 |
| GET | `/api/kits/{kit_id}` | 获取单个锦囊详情 |
| PUT | `/api/kits/{kit_id}` | 更新锦囊字段 |
| POST | `/api/kits/{kit_id}/bind-node` | 绑定导航节点到锦囊 |
| DELETE | `/api/kits/{kit_id}/bind-node/{node_id}` | 解绑导航节点 |
| POST | `/api/kits/{kit_id}/next/{target_id}` | 从锦囊添加出向连接（可指向导航节点） |
| DELETE | `/api/kits/{kit_id}/next/{target_id}` | 删除锦囊的出向连接 |

### 4.3 现有端点适配

| 现有端点 | 适配说明 |
|----------|----------|
| `GET /api/nodes` | `q` 参数扩展到搜索锦囊的 name/trigger/mechanism |
| `POST /api/plan/generate` | `waypoint_ids` 可包含 `kit_*` ID |
| `GET /api/browse/cards` | 当当前节点类型为 kit 时，返回锦囊 body 而非卡片列表 |
| `GET /api/connections/status/{from_id}/{to_id}` | 支持跨类型查询（nav→kit, kit→nav, kit→kit） |

## 5. CLI 扩展

### 5.1 `kn-backend` 新增子命令

```
kn-backend kit
├── list [--json]                   # 列出所有锦囊
├── get <id> [--json]              # 查看锦囊详情
├── update <id> <field> <value>    # 更新字段
├── bind                           # 绑定管理
│   ├── list <id>                  # 列出绑定节点
│   ├── add <kitId> <nodeId>       # 绑定
│   └── remove <kitId> <nodeId>    # 解绑
└── next                           # 出向连接管理
    ├── list <id>                  # 列出出向连接
    ├── add <fromId> <toId>        # 添加连接（可指向 nav 节点）
    └── remove <fromId> <toId>     # 删除连接
```

### 5.2 现有命令兼容

```
kn-backend node next add node-1 kit_b         # 导航节点 → 锦囊
kn-backend plan generate node-a,kit_b,node-c  # 混合途经点
kn-backend connect status node-1 kit_b        # 跨类型状态查询
```

## 6. 前端适配

### 6.1 节点类型枚举

```typescript
export type NodeType = 'nav_node' | 'kit'
```

### 6.2 混合渲染

导航画布按 `node_type` 区分渲染样式：

| 节点类型 | 形状 | 颜色 | 说明文字 |
|----------|------|------|----------|
| `nav_node` | 圆形 | 主题色 | label |
| `kit` | 菱形 | `kit_specific.color` | `kit_specific.letter + name` |

### 6.3 浏览模式中的锦囊展示

当浏览到锦囊类型节点时，浏览界面切换为"引导词展示模式"：

```
╔══════════════════════════════════════╗
║  锦囊 B · 迷失预警                    ║
║                                      ║
║  状态正在流转——这是正常的，不是失败。  ║
║  迷失不是你的错...                    ║
║                                      ║
║  回到感官锚点：呼吸，身体感觉，        ║
║  环境中的声音。                        ║
║                                      ║
║  ─── 下一站 ───                      ║
║  锦囊 E · 回归执行者                  ║
╚══════════════════════════════════════╝
```

### 6.4 开关：是否混合锦囊与导航节点

在导航画布设置中增加开关：

```
☑ 在导航图中显示锦囊节点
☑ 路线规划可包含锦囊
```

默认均为开启状态，关闭后锦囊从图谱和规划选项中隐藏。

## 7. 路径涌现引擎联动

### 7.1 涌现输出映射为导航节点

涌现引擎的输出（`emergent_kit` + `predicted_path`）可自动映射为临时导航计划：

```
涌现引擎输出：
  primary_card: card_05
  recommended_kit: kit_b
  predicted_path: [kit_b, kit_e, kit_f, kit_g]
    │
    ▼
映射为导航途经点序列：
  [kit_b, kit_e, kit_f, kit_g]
    │
    ▼
自动进入路线规划视图，用户可：
  - 直接采纳为导航计划
  - 混入其他导航节点重新规划
  - 逐一进入浏览模式体验锦囊引导词
```

### 7.2 双向连接

涌现引擎使用导航图谱中的连接信息优化路径预测：

```
路径涌现规则增强：
  - from_designer_stuck:
      entry_kit: kit_b
      predicted_path:
        若 kit_b → node-X 连接存在 → [kit_b, node-X, ...]
        若 kit_b → node-X 不存在 → [kit_b, kit_e, ...]
```

## 8. 验收标准

- [ ] 锦囊数据模型与导航节点可互相转换（统一 GraphNode 接口）
- [ ] 导航图谱同时渲染 NavNode 和 Kit 两种节点
- [ ] 路线规划途经点可混合包含 NavNode 和 Kit
- [ ] 浏览序列中的 Kit 节点展示引导词而非认知卡片
- [ ] 搜索同时索引锦囊的 name/trigger/mechanism 字段
- [ ] 快捷连接支持 NavNode↔Kit、Kit↔Kit、Kit↔NavNode
- [ ] `kits.json` 新增 `next_nodes` 和 `bound_cards` 字段，向后兼容
- [ ] YAML 导入导出将锦囊作为 `node_type: kit` 的导航节点
- [ ] 后端 `/api/kits` 端点可查询和管理锦囊
- [ ] 前端按 node_type 区分渲染样式（圆形 vs 菱形）
- [ ] 前端有开关控制锦囊是否在导航图中显示
