# 与 cognitive-cards 文档体系的关联：向量检索与涌现引擎

> 关联对象（`cognitive-cards/docs/`）：
> 1. 《知识库与本地向量模型使用指南》—— AstrBot 知识库管道与本地嵌入配置
> 2. 《backend-vector-roadmap》—— 认知卡片后端的 FAISS + FTS5 混合检索路线图
> 3. 《涌现引擎：用户输入到锦囊路径生成》—— 三阶段「匹配 → 细化 → 涌现」设计
>
> 本文说明这三份文档与 **knowledge-navigator-react**（本项目）当前实现的对应关系、
> 已落地的部分、以及可预见的演进路径。

---

## 1. 一句话总览

cognitive-cards 是**内容与方法论源头**（认知卡片、语料、锦囊定义与循环理论），
knowledge-navigator-react 是它的**导航与交互载体**（把卡片和锦囊组织成可搜索、
可规划、可浏览的导航图）。三份文档分别对应本项目的：嵌入基础设施（已落地）、
检索引擎升级路线（部分落地）、以及尚未实现的「涌现」能力（未来方向）。

---

## 2. 《知识库与本地向量模型使用指南》 × 本项目

**该文档核心**：AstrBot 的「解析 → 分块 → 嵌入 → 向量库 → 检索」管道，以及通过
**OpenAI 兼容 `/v1/embeddings`** 接入本地 LM Studio / Ollama 嵌入模型的配置方法。

**本项目已落地**：

| 文档中的模式 | 本项目对应实现 |
|---|---|
| OpenAI 兼容 `/v1/embeddings`（`api_base: http://localhost:1234/v1`） | `backend/app/routers/search.py` 的 `_embed()`，同一端点、同一协议 |
| 推荐模型 `nomic-embed-text-v1.5`（768 维） | 本项目嵌入候选模型之二，实测为当前可用主力（query 与 37 张卡片批量嵌入） |
| 文档推荐的 `bge-large-zh-v1.5`（中文最佳） | 候选模型之一 `text-embedding-qwen3-embedding-0.6b` 目前加载失败；若修复或换 bge 系，中文语义排序会更准——文档 §4.6 的模型推荐表直接适用于本项目 |
| 连接失败的排查清单（§8） | 本项目 `_embed()` 全部候选失败时返回 `None`，端点自动降级关键词评分——即文档「本地 LM 连接失败」场景的工程化处理 |

**与文档的差异**：AstrBot 有完整的文档解析/分块管道（它检索的是上传文档的 chunks）；
本项目检索对象是结构化的认知卡片（标题+描述+语料），无需解析与分块，每条卡片直接对应一个向量。
这与 roadmap 文档 §2.4.2 的「关键差异」判断一致。

## 3. 《backend-vector-roadmap》 × 本项目

**该文档核心**：把认知卡片后端从「Jaccard 关键词 + 内存 JSON」升级为
「FAISS 稠密检索 + SQLite FTS5 稀疏检索 + RRF 融合 + LLM/模板双路径涌现」的完整设计。

**本项目的位置：已走出该路线图的「第 0 步」**。

| Roadmap 模块 | 本项目现状 | 差距 |
|---|---|---|
| `EmbeddingService`（批量、缓存、降级标志） | `_embed()` 实时批量嵌入，**无缓存**——每次搜索都重新嵌入全部 37 张卡片 | 缺文本→向量缓存与 `_available` 降级标志（当前每次请求都重试连接） |
| `FaissVecDB`（FAISS 索引 + SQLite 文档存储） | 未引入 FAISS；纯 Python 暴力余弦（37 张卡片规模下延迟可接受） | 数据量增长到数百张以上时需要索引；roadmap 的 `IndexFlatL2 + IndexIDMap + normalize_L2` 模式可直接照搬 |
| `SparseRetriever`（FTS5 BM25 稀疏检索） | 无稀疏检索；关键词模式是前端本地加权子串评分 | 向量 + BM25 双路是混合检索的前提 |
| `RankFusion`（RRF k=60 融合） | 无 | 在双路检索就绪后按 roadmap §2.3 直接实现 |
| `IndexBootstrap`（启动批量建索引） | 无（无索引可建） | 引入 FAISS 后的启动流程参考 §2.5 |
| LLM/模板双路径（`emergence.py`） | **已有雏形**：`/api/ai/generate/*` 走 LM Studio qwen，失败自动模板降级——与 roadmap §4.3 的降级树同一思想 | 目前只有字段级生成（标题/描述），还没有引导词级生成 |

**结论**：本项目当前的 `/api/search/vector-match`（实时嵌入 + 余弦 Top-8 + 关键词降级）
是 roadmap 架构的**最小可行版本**。roadmap 中的 EmbeddingService 缓存、FAISS 索引、
FTS5 + RRF 混合检索是下一步升级的现成蓝图，且文档 §6 的「直接可复用的 AstrBot 模式」
清单同样适用于本项目后端。

## 4. 《涌现引擎：用户输入到锦囊路径生成》 × 本项目

**该文档核心**：用户一段自由输入 → 阶段一语义匹配卡片 → 阶段二语料细化 →
阶段三 LLM 涌现锦囊引导词，并沿「锦囊环路」（B 迷失预警 → E 回归执行者 →
F 具身认知 → G 复盘提取，含 H 提前复盘风险预警）推演整条路径。

**本项目与三阶段的对应关系**：

| 涌现引擎阶段 | 本项目已有的对应能力 | 状态 |
|---|---|---|
| 阶段一：语义匹配卡片 | 搜索视图「向量模型匹配」：自然语言 → 嵌入 → 命中卡片（实测「如何走出低谷重新振作」命中锦囊 D 居首） | ✅ 已落地（完整模式（pro）） |
| 阶段一附件：用户状态分析（心态/循环位置/风险信号） | 无——匹配只产出卡片与分数，没有 LLM 状态分析 | ❌ 未实现 |
| 阶段二：语料细化（quality × style × keyword 评分） | 卡片的语料库字段已在数据模型与管理界面中可编辑，但无按用户输入细化筛选 | ❌ 未实现 |
| 阶段三：LLM 涌现引导词（感官意象 + 身体动作指令） | `/api/ai/generate/*` 有 LLM 调用与模板降级管道，但提示词是字段生成型，不是引导词型 | 🔶 管道已有，提示词未接 |
| 路径推演（kit_B → E → F → G + kit_H 风险预警） | **数据已就绪**：心智工具箱 8 锦囊已作为导航节点导入（node-kit 环路，A–H 全在导航图中）；规划视图可对途经点生成路线 | 🔶 图结构已有，规则引擎未接 |

**关键洞察**：涌现引擎的「预测路径」本质上就是本项目**路线规划在锦囊环路上的一个特化**——
roadmap 文档的 `path_emergence_rules`（from_designer_stuck 等四条规则）可以翻译成
导航节点上的预设连接权重与约束（如「执行者具身完成前禁止跳到 kit_G」就是一条带条件的边）。
本项目的导航图 + 权重规划算法，是涌现规则引擎的天然宿主。

**若要把涌现引擎搬进本项目，最小实现路径**：

1. 搜索视图增加「状态分析」：命中卡片后调 `/api/ai` 用涌现文档 §7.2 的匹配器提示词产出心态/位置/风险
2. 规划视图增加「锦囊路径」模式：沿 node-kit 环路按 `path_emergence_rules` 生成路线（替代通用权重规划）
3. 浏览视图在锦囊站点展示涌现引导词：`/api/ai` 换用涌现器提示词（感官意象 + 身体动作），模板降级取锦囊默认文案
4. 阶段二的语料细化可在后端 `search.py` 旁新增 `refine` 端点，评分公式直接采用文档 §3.3

## 5. 数据血缘

```
cognitive-cards/                     （内容源头）
  ├── 认知卡片 + 语料库        ──┐
  └── 锦囊（kit A–H 循环理论）   ─┤
                                 ▼
       scripts/generate-mind-toolbox-yaml.py   （本项目转换脚本）
                                 ▼
       backend/data.yaml         37 卡片（含 10 心智工具箱卡 + 8 锦囊卡）
                                 25 节点（含 node-kit A–H 环路）
                                 ▼
       knowledge-navigator-react 五视图：搜索 / 导航 / 规划 / 浏览 / 管理
```

三份文档则为这条数据流之上的**智能层**提供了完整设计：嵌入基础设施（指南）、
检索引擎升级（roadmap）、以及「理解即引导」的涌现能力（涌现引擎）。
