## 一、动机

### 1.1 现状

目前只有一个全局的活动图选择器（StatusBar 中的图切换 Dropdown），切换后：
- 全览画布只渲染当前活动图的节点
- 逐站画布也只展示当前活动图的节点
- 后端的所有 API 请求都携带 `?graph=当前图ID` 参数

钻入子图后，StatusBar 自动切换活动图以显示子图内容。

### 1.2 问题

| 问题 | 说明 |
|------|------|
| 无法跨图对比 | 用户想同时在画布上看到"机器学习"和"认知心理学"的相关节点，需要切图查看 |
| 子图节点边界模糊 | 在全览画布上无法直观看到当前图中哪些节点是"子图节点"（可钻入） |
| 缺乏全局视图 | 系统存在多个导航图，但用户没有"一览全貌"的入口 |
| 钻出后恢复位置 | 钻出后活动图恢复到父图，但父图的全览画布可能已遗忘之前选中的节点位置 |

### 1.3 目标

1. **多选 checkbox 加载**：顶层 top 画布通过多选框选择要加载的导航图，支持全选
2. **多图融合渲染**：选中的多个图的节点和边在同一画布渲染，ID 做命名空间化
3. **图选择器与钻入/钻出状态联动**：钻入时自动切换、钻出时恢复
4. **多图模式下的节点来源标注**：每个节点需标注其所属图

## 二、核心概念

### 2.1 两种模式

导航画布有两种展示模式：

| 模式 | 条件 | 说明 |
|------|------|------|
| **Top 多图模式** | `breadcrumb = ["top"]` | 通过多选框选择 N 个图，画布融合渲染它们的节点和边 |
| **子图单图模式** | `breadcrumb` 长度 > 1 | 已钻入子图，画布只渲染当前子图的节点 |

### 2.2 分层状态

| 概念 | 作用域 | 说明 |
|------|--------|------|
| `selectedGraphIds` | 画布（navStore） | Top 模式下多选框选中的图 ID 列表 |
| `activeGraphId` | 全局（graphStore） | 后端 API 的 `?graph=` 参数来源，钻入时跟随 |
| `breadcrumb` | 导航（drillStore） | 当前钻入路径，`["top"]` 表示顶层 |

**三者关系：**
- Top 模式下：`activeGraphId` 取 `selectedGraphIds[0]` 作为 API 默认参数，画布渲染所有选中图
- 钻入时：`activeGraphId` 切换到子图 ID，`breadcrumb` 追加子图 ID
- 钻出时：`activeGraphId` 恢复父图 ID，`breadcrumb` 弹出栈顶

## 三、状态管理

### 3.1 navStore 新增字段

```typescript
// src/store/navStore.ts
interface NavStore {
  // ……已有字段……

  /** Top 模式下多选框选中的图 ID 列表（空 = 不渲染任何图） */
  selectedGraphIds: string[]

  /** 是否全选 */
  isAllSelected: boolean

  /** 设置选中的图列表 */
  setSelectedGraphs: (ids: string[]) => void

  /** 切换全选/取消全选 */
  toggleSelectAll: () => void

  /** 切换某个图的选中状态 */
  toggleGraph: (graphId: string) => void

  /** 根据 selectedGraphIds 返回当前画布应渲染的节点列表（含命名空间化） */
  getCanvasNodes: () => NamespacedNode[]

  /** 根据 selectedGraphIds 返回当前画布应渲染的边列表 */
  getCanvasEdges: () => NamespacedEdge[]
}
```

### 3.2 命名空间化

为防止不同 YAML 中的 `id` 冲突，所有节点和边在加载时做命名空间化：

```typescript
interface NamespacedNode extends NavNode {
  _nsId: string             // "{graph_id}::{node_id}"
  _sourceGraphId: string
  _sourceGraphLabel: string
}

function namespacedNodes(graphs: Graph[]): NamespacedNode[] {
  return graphs.flatMap(g =>
    g.nodes.map(n => ({
      ...n,
      _nsId: `${g.graph_id}::${n.id}`,
      _sourceGraphId: g.graph_id,
      _sourceGraphLabel: g.label,
    }))
  )
}
```

### 3.3 钻入/钻出时的联动

```
用户勾选 [g1, g2] → breadcrumb = ["top"] → 画布渲染 g1+g2 融合

用户点击子图节点 → drillIn()
  1. breadcrumb → ["top", "g1"] 追加目标子图 ID → ["top", "g1", "bbb_id"]
  2. activeGraphId → 目标子图 ID
  3. 画布切换到子图单图模式（只看子图内容）
  4. selectedGraphIds 保留钻入前的值（钻出后恢复）

用户钻出
  1. breadcrumb 弹出栈顶
  2. activeGraphId → 父图 ID
  3. 画布恢复到 Top 多图模式，用之前保留的 selectedGraphIds 渲染
```

## 五、数据流

### 5.1 获取画布数据

```typescript
// navStore 中的 getCanvasNodes 实现示意
getCanvasNodes: () => {
  const { breadcrumb, selectedGraphIds, graphs } = get()

  if (breadcrumb.length > 1) {
    // 钻入模式：只看当前子图
    const currentGraphId = breadcrumb[breadcrumb.length - 1]
    const graph = graphs.find(g => g.graph_id === currentGraphId)
    return graph ? namespacedNodes([graph]) : []
  }

  // Top 模式：渲染选中的图
  const selected = graphs.filter(g => selectedGraphIds.includes(g.graph_id))
  return namespacedNodes(selected)
}
```

### 5.2 钻入/钻出与选择器的交互

```
状态机：

  [Top 多图模式]  ← 已选 [g1, g2] → 画布融合渲染
     |
     |  用户点击子图节点 → drillIn()
     |    → breadcrumb: ["top"] → ["top", "g1", "bbb_id"]
     |    → activeGraphId: "g1" → "bbb_id"
     |    → 画布切换到子图单图模式
     v
  [子图单图模式]  ← 仅渲染子图 bbb_id 内容
     |
     |  用户点击钻出 → drillOut()
     |    → breadcrumb: ["top", "g1", "bbb_id"] → ["top", "g1"]
     |    → activeGraphId: "bbb_id" → "g1"
     |    → 画布回到 Top 多图模式，恢复 selectedGraphIds
     v
  [Top 多图模式]  ← 恢复融合渲染
```

**关键规则**：
- 钻入时 `selectedGraphIds` 保持不动（快照），钻出时恢复
- 钻入状态不可切换多选框（多选框区域禁用或收起）
- 钻出后自动恢复到钻入前的多选组合

## 六、边界情况

| 场景 | 行为 |
|------|------|
| 一个图都没选 | 画布显示空状态提示"请选择至少一个导航图" |
| 全量模式下点击子图节点 | 钻入子图，多选框区域收起，画布显示单图 |
| 多图模式下跨图节点点击 | 保持多图模式，仅高亮该节点（不切换图） |
| 选中的图被删除 | Toast 提示"图 xxx 已被删除"，自动从 selectedGraphIds 移除 |
| 钻出后某个之前选中的图已不存在 | 自动移除，Toast 提示 |
| 无后端（lite 模式） | 只有一个图，默认勾选，多选框隐藏或禁用 |
| 全选后新增了一个图 | 自动勾选新图（全选状态下新增图默认选中） |
