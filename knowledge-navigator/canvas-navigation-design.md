# 认知导航 — 画布交互设计分析

## 一、三层画布视图的技术选型与设计

### 1. 全局全览 — 有向有环图（Directed Cyclic Graph）

**场景**：展示所有认知卡片节点及路径节点之间的关联关系，支持搜索匹配后高亮定位，节点之间存在循环引用（如"机器学习→深度学习→神经网络→机器学习"）。

**推荐方案：D3-force 力导向图**

D3 的 `d3-force` 模块是处理此类图的最成熟方案：

| 能力 | D3-force | vis-network | Cytoscape.js | G6 (AntV) |
|------|----------|-------------|--------------|-----------|
| 力导向布局 | 原生支持，参数可控 | 内置 | 内置 | 内置 |
| 有向边/箭头 | 通过 marker-end 实现 | 原生 | 原生 | 原生 |
| 环形路径处理 | 需自定义曲线 | 自动 | 自动 | 自动 |
| 移动端触摸 | 需手动绑定 | 部分支持 | 较好 | 较好 |
| 包体积 | 模块按需加载 | ~800KB | ~500KB | ~600KB |
| 定制自由度 | 极高（SVG/Canvas） | 中 | 中 | 中 |

**推荐 D3-force 的理由**：
- 项目已有 SVG 基础设施（Lucide 图标），D3 直接操作 SVG/DOM，无需引入额外抽象层
- 力导向模拟的参数（电荷力、碰撞检测、中心力）可精细控制节点分布密度，适配移动端卡片式展示
- `d3-force` 的 `linkDistance` 和 `linkStrength` 可直接映射到路径节点的"权重"概念——权重越大的边距离越短、引力越强
- 循环边的可视化通过 `d3-shape` 的曲线插值（`d3.curveBundle` 或自绘制贝塞尔弧线）处理

**设计要点**：
- 节点用圆形+标签，匹配到的节点用暖琥珀色高亮（`--primary`）并放大
- 边用带箭头曲线，权重高的边更粗，颜色更深
- 画布支持双指缩放/拖拽平移，单击节点进入路径选择视图
- 搜索匹配时，以匹配节点为中心做弹性聚焦动画（`d3-transition`）

---

### 2. 路径选择 — 有向无环图（DAG）+ 流程图

**场景**：展示当前节点在上一步/下一步之间的局部路径流。底部为上一节点，中间为当前节点（高亮），顶部为下一步候选节点列表。方向是自底向上的有向无环结构。

**推荐方案：D3-hierarchy（Tree Layout）+ 自定义垂直流向**

当前 `path-select.html` 已采用 CSS 静态垂直流布局。要升级为画布交互，推荐以下分层方案：

**方案 A：D3-tree + 固定方向（推荐用于简单路径）**
- `d3.tree()` 设置固定方向为自底向上（`nodeSize` 控制间距）
- 每个节点的子节点即为其"下一步"候选
- 优势：D3-hierarchy 原生支持树/DAG 布局，自动计算坐标

**方案 B：elkjs + SVG 渲染（推荐用于复杂分支）**
- [elkjs](https://github.com/kieler/elkjs) 是 Eclipse 的图布局引擎 JS 版本
- 原生支持 `layered` 布局算法（Sugiyama 算法），专为 DAG 设计
- 能处理多层级、跨层边、端口约束
- 包体积 ~700KB，但布局质量远优于手写

**对比**：

| 特性 | D3-tree | elkjs |
|------|---------|-------|
| 简单父子路径 | 开箱即用 | 需配置 |
| 多分支/跨层连线 | 困难 | 原生 |
| 节点权重视觉映射 | 自定义 | 自定义 |
| 学习成本 | 低（D3 生态） | 中 |

**推荐 elkjs + D3 渲染**：
- 认知导航的路径节点不是简单树——一个节点可能从不同的前驱到达，也可能有多个后继，DAG 特性需要 elkjs 的 layering 算法
- elkjs 输出节点坐标后，用 D3 的 `d3-shape` 绘制连线（`d3.linkVertical` 或自定义贝塞尔路径）
- 权重映射：连接线的粗细/透明度 = 权重值，预设权重用实线、浏览权重用虚线

**设计要点**：
- 当前节点居中高亮，上方动态展开"下一步"候选卡片（按权重排序）
- 点击候选节点后，路径流动画过渡，节点上移/下移
- 上拉面板（pull-up panel）用弹性动画（`d3-ease`），承载节点编辑功能
- 连线颜色从暖琥珀（当前→未来）到暖灰（过去→当前）渐变

### 3. 树形管理 — 文件夹/Tree 视图

**场景**：认知卡片的层级管理，路径格式如 `root/1`、`root/1/2`，`root` 仅为根目录标识。支持展开折叠、搜索、编辑。

**推荐方案：原生 DOM + 轻量交互增强**

当前 `tree-manager.html` 已实现基础 DOM 树形视图，这是正确的技术选型。理由：

| 方案 | 适用场景 | 不适合的原因 |
|------|---------|-------------|
| 原生 DOM 树 | 列表式层级数据，需要文本选中、表单编辑 | —（推荐） |
| D3-tree Canvas/SVG | 需要全局视角的树图可视化 | 文字渲染差、编辑困难、触摸选择不友好 |
| React Tree 组件 | 需要虚拟滚动的大量节点 | 引入框架增加复杂度 |

**增强建议**：
- 保持当前 DOM 结构，用 **虚拟滚动**（[virtua](https://github.com/inokawa/virtua) 或手写 IntersectionObserver）优化大量节点时的性能
- 拖拽排序：使用 [SortableJS](https://sortablejs.github.io/Sortable/) 实现认知卡片在树中的拖拽移动（如将 `root/1/2` 拖到 `root/2` 下变为 `root/2/2`）
- 路径面包屑导航：顶部显示当前编辑卡片的完整路径（`root > 机器学习 > 监督学习`）
- 搜索过滤：输入时实时折叠不匹配的分支，高亮匹配节点

## 二、地图导航 vs 认知导航 — 设计异同分析

### 异同对比表

| 维度 | 地图导航 | 认知导航 | 设计启示 |
|------|---------|---------|---------|
| **空间模型** | 物理二维/三维空间，经纬度坐标 | 抽象概念空间，节点通过语义关联 | 前者可用绝对坐标，后者必须用关系网络表达 |
| **路径特性** | 最短路径优先（距离/时间），通常单一起终点 | 多路径可选，受权重（预设/浏览）影响，支持中途变更 | 需要同时展示多条候选路径，并标注权重差异 |
| **方向性** | 道路有方向（单行道/双向），全局拓扑基本已知 | 节点间关系有向，但可根据用户行为动态演化 | 需支持循环路径和动态边权重更新 |
| **缩放层级** | 城市级→街区级→道路级，瓦片地图自然支持 | 全局全览图→路径流程图→内容卡片，抽象层级递进 | 三层视图本质是三个缩放层级的认知地图 |
| **导航模式** | 路线规划→跟随导航（turn-by-turn） | 输入匹配→路径选择→内容浏览（滑动） | 浏览模式类似"沿路径行走"，而非"地图上看路线" |
| **定位方式** | GPS 绝对定位 | 文本搜索模糊匹配→认知卡片定位 | 搜索是认知导航的"GPS"，需要高亮匹配结果 |
| **POI** | 餐厅、加油站等地标 | 认知卡片（标题+描述+语料库） | 认知卡片 = 知识地标，支持嵌套子结构 |

### 核心差异

1. **地图是静态拓扑，认知图是动态拓扑**
   - 地图的路径基本不变，而认知导航中用户浏览行为会生成新的权重边，图结构持续演化
   - 前端需要支持运行时动态增删节点和边

2. **地图导航强调"到达"，认知导航强调"探索"**
   - 地图的结束是到达目的地，认知的结束可能是"发现了一个新概念"
   - UI 不应只显示一条最优路径，而应保留浏览的分支可能性

3. **地图有统一的底图坐标系，认知图没有**
   - 地图可以用瓦片（tile），认知图每次布局都可能不同
   - 力导向布局每次初始化的节点位置不同，需要存储布局快照或使用固定坐标

### 适合的前端效果

| 效果 | 技术 | 适用场景 |
|------|------|---------|
| **力导向弹性动画** | d3-force + d3-transition | 全览图节点拖拽、搜索聚焦 |
| **路径流动粒子** | SVG stroke-dashoffset 动画 | 路径选择视图中表示"行进方向" |
| **卡片堆叠过渡** | CSS transform + cubic-bezier | 内容浏览的上下滑动（已是当前实现） |
| **节点脉冲高亮** | SVG filter + animation | 搜索匹配时标记目标节点 |
| **边权重渐变** | SVG gradient along path | 展示预设权重和浏览权重的混合比例 |
| **树节点展开折叠** | CSS height transition | 树形管理的目录展开（已是当前实现） |
| **面包屑导航** | CSS flex + 箭头分隔符 | 路径选择视图显示当前位置上下文 |

## 三、各视图的 D3 实现路径

### 全览图（Force Graph）

```
数据结构：{ nodes: [{id, label, type: "card"|"path"}], links: [{source, target, weight, type: "preset"|"browse"}] }

核心模块：
- d3-force (forceSimulation, forceLink, forceManyBody, forceCenter, forceCollide)
- d3-selection (data join 创建/更新节点和边)
- d3-zoom (画布缩放平移)
- d3-shape (曲线边路径)
- d3-transition (搜索聚焦动画)

交互：
- 拖拽节点 → simulation.alphaTarget(0.3).restart()
- 搜索 → 高亮匹配节点，d3-zoom.transform 移动到视口中心
- 点击节点 → 跳转到路径选择视图
```

### 路径流程图（DAG Flow）

```
数据结构：{ currentNode, prevNodes: [...], nextNodes: [{id, label, presetWeight, browseWeight}] }

核心模块：
- elkjs (layered 布局算法计算坐标)
- d3-shape (linkVertical, linkHorizontal 连线)
- d3-transition (节点切换动画)

交互：
- 点击下一步候选 → 该节点变为当前节点，重新计算布局，动画过渡
- 上拉面板 → d3-ease 弹性动画
```

### 树形管理（DOM Tree）

```
保持当前 DOM 方案，增强：
- SortableJS 拖拽
- IntersectionObserver 虚拟滚动
- 搜索过滤（CSS 类切换显示/隐藏）
```

## 四、推荐的库组合

| 视图 | 推荐库 | CDN |
|------|-------|-----|
| 全局全览 | d3-force + d3-zoom + d3-selection | `d3@7` 完整包 ~280KB（按需拆模块更小） |
| 路径选择 | elkjs + d3-shape + d3-transition | elkjs 单独引入 |
| 树形管理 | SortableJS | `sortablejs@1` ~30KB |

如果追求最小包体积：全览图和路径流程图可统一用 **Cytoscape.js**（一次引入覆盖力导向+DAG布局+移动端触摸），代价是定制自由度降低。

**最终建议**：当前项目已有完整的静态 HTML 原型，引入 D3 做全览图的力导向交互和路径流程图的 elkjs 布局，树形管理保持 DOM 方案，是增量改造成本最低的路径。
