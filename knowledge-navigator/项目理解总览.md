# Knowledge Navigator — 项目理解总览

> 基于 `design.md`、`feature-spec-react.md`、`react-migration-plan.md`、`data-model.md` 四份文档的综合理解。

## 一、项目定位

**Knowledge Navigator（认知导航器）** 是一款以"知识图谱 + 路径导航"为核心隐喻的个人知识管理应用。它将传统意义上的"知识库"重新建模为一张可导航的地图——用户搜索概念（像搜索地点）、规划学习路径（像规划路线）、逐站浏览内容（像按导航行驶）。

核心设计哲学：**认知卡片回答"是什么"，导航节点回答"走向哪里"**。两者解耦又可绑定，形成灵活的知识网络。

## 二、四层界面架构

```
┌─────────────────────────────────────────────────────────────┐
│  ① 搜索视图 (SearchView)                                      │
│     文本输入 → 模糊匹配认知卡片 → 查询绑定节点 → 选中进入导航    │
│     类比：地图 App 中搜索"咖啡馆"→ 出现地点列表                │
├─────────────────────────────────────────────────────────────┤
│  ② 导航视图 (NavView) — 双模式画布                             │
│     • 全览模式：D3 力导向图，展示全部节点与连接                │
│     • 逐站模式：DAG 流，展示前驱/当前/后继三层布局             │
│     • 途径点序列：可添加/删除/重排多个经停点                    │
│     • 下拉面板：点击节点弹出，可查看详情、添加为途径点          │
│     类比：地图导航中选点 → 添加途经点 → 规划完整路线            │
├─────────────────────────────────────────────────────────────┤
│  ③ 浏览视图 (BrowseView)                                      │
│     按途径点顺序加载认知卡片，类抖音上下滑动切换                 │
│     支持语料库展开、关联节点展示、途径点进度指示                 │
│     类比：按导航顺序行驶，每到一站查看该站的详细信息              │
├─────────────────────────────────────────────────────────────┤
│  ④ 树形管理 (TreeView)                                        │
│     认知卡片的层级化管理：搜索、编辑、创建、删除                 │
│     扁平 YAML 存储 → 运行时推导嵌套树结构                       │
│     类比：文件资源管理器，管理知识库的结构                       │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 与原版的架构变更

| 维度 | 原版 (单文件 HTML) | React 版 |
|------|-------------------|----------|
| 入口视图 | GlobalView（力导向全览图） | **SearchView**（文本搜索→卡片→节点） |
| 导航视图 | NavView（DAG 逐站流，独立） | **NavView**（力导向 + DAG 双模式合并） |
| 路线规划 | 单一起止点 | **多途径点序列**（waypoints） |
| 状态管理 | 闭包全局对象 | **Zustand 6 切片** |
| 渲染方式 | innerHTML 字符串拼接 | **JSX 声明式 + 条件渲染** |

## 三、两大核心数据模型

### 3.1 认知卡片（Cognitive Card）—— "知识单元"

```yaml
# 扁平 YAML 存储示例
cognitive_cards:
  - id: root/1        # 层级路径 = 父子关系标识
    title: 机器学习
    type: folder      # folder(可展开) / leaf(叶子)
    corpus: ["..."]   # 语料库，用于匹配与自动生成
    tag: 层级分类      # "决策分支" | "层级分类"
    bound_nodes: [node-ml-foundation]  # 绑定的导航节点

  - id: root/1/1
    title: 监督学习
    type: leaf
    corpus: ["..."]
    tag: 决策分支
    bound_nodes: [node-supervised]
```

**关键设计**:
- **扁平存储，层级推导**：`parent`/`children` 不在 YAML 中存储，运行时从 `id` 路径推导（`root/1/1` 的 parent 是 `root/1`）
- **两种子节点语义**：`"决策分支"`（i叉树选择结构）、`"层级分类"`（上下级包含关系）
- **自动生成能力**：通过语料库或子节点描述反向生成父节点的标题/描述
- **绑定导航节点**：一张卡片可被多个导航节点引用，实现"一处定义，多处使用"

### 3.2 导航节点（Navigation Node）—— "航线坐标"

```yaml
navigation_nodes:
  - id: node-ml-foundation
    label: 机器学习基础
    description: "..."
    bound_cards: [root/1, root/3]   # 绑定的认知卡片
    next_nodes:                     # 出向连接（可跳转的下一站）
      - target_id: node-supervised
        preset_weight: 0.75         # 预设权重
        browse_weight: 0.42         # 浏览行为权重
        connection_type: preset
    priority_config:
      mode: mixed                   # mixed(混合) | user_only(纯用户)
      preset_priority: 0
      browse_priority: 1
      user_overrides: []            # 用户手动覆盖权重
```

**关键设计**:
- **双权重机制**：`preset_weight`（设计者预设）+ `browse_weight`（用户浏览行为累积）
- **混合/纯用户双模式**：混合模式将两类权重按优先级拼接为总序列；纯用户模式忽略浏览记录
- **权重优先级**：`user_overrides` > `preset_weight` > `browse_weight`
- **浏览历史记录**：`browse_history` 记录从哪些节点跳转过来及频次，用于动态调整权重

## 四、核心导航工作流

```
用户输入 "监督学习"
    ↓
模糊匹配认知卡片（title / description / corpus）
    ├─ 机器学习         (root/1)
    ├─ 监督学习         (root/1/1)  ← 高亮
    └─ 无监督学习       (root/1/2)
    ↓
选中「监督学习」→ 查询其 bound_nodes
    ├─ node-supervised      ← 绑定
    ├─ node-ml-foundation   ← 绑定
    └─ node-deep-learning   ← 未绑定
    ↓
选中 node-supervised → 点击「进入导航」
    ↓
进入 NavView（默认全览模式）
    → 力导向图中高亮当前节点
    → 点击其他节点 → 下拉面板 → "添加为途径点"
    → 途径点序列：[监督学习] → [神经网络] → [深度学习]
    ↓
点击「开始浏览」
    → 按途径点顺序加载认知卡片
    → 第 1/3 站 · 上下滑动切换卡片
    → 「下一站」→ 第 2/3 站
```

## 五、技术栈与架构

### 5.1 技术选型

| 层 | 技术 | 理由 |
|---|------|------|
| 框架 | React 18 + TypeScript | 组件化、类型安全 |
| 构建 | Vite | HMR 热更新开箱即用 |
| 状态 | Zustand | 轻量、无样板代码、支持中间件 |
| 可视化 | D3.js v7 | 力导向图 + DAG 布局 |
| 样式 | CSS Modules + CSS Variables | 组件隔离 + 深色主题复用 |

### 5.2 状态管理（6 个 Zustand Store）

```
viewStore     → activeView 切换（search/nav/browse/tree）
searchStore   → 搜索查询 + 卡片匹配 + 节点选中
panelStore    → 下拉面板状态（node/position/syncVisibility）
navStore      → 导航模式 + 途径点序列 + D3 数据 + 权重排序
browseStore   → 卡片浏览 + 途径点进度 + 滑动切换
treeStore     → 扁平树数据 + 展开/选中/搜索过滤
```

### 5.3 D3 集成策略

- **统一 Hook**：`useNavCanvas` 合并原 `useForceGraph` + `useDagFlow`
- **双实例共存**：内部维护 forceSimulation + DAG layout 两个 D3 实例，mode 切换时切换可见 SVG group，不销毁
- **React 管生命周期，D3 管数学/渲染**：清晰的职责分离

## 六、关键设计亮点

### 6.1 搜索驱动的导航入口
原版以"全览力导向图"作为入口，信息密度过高。React 版改为**搜索优先**——用户先输入概念，再定位到具体节点，降低了认知负荷。

### 6.2 多途径点路线规划
借鉴地图导航的"途经点"概念，用户可在画布上点击多个节点构建有序序列 `[A] → [B] → [C]`，然后按顺序浏览。这是原版不支持的核心新增能力。

### 6.3 权重可溯源的透明算法
每个连接权重明确标记来源：`preset`（设计预设）、`browse_derived`（浏览行为生成）、`user_added`（用户手动添加）。混合模式下的排序算法透明可预期。

### 6.4 扁平存储 + 算法推导树结构
YAML 中不存储 `parent`/`children`，避免数据冗余和不一致。运行时从 `id` 层级路径自动推导，支持无限层级嵌套。

### 6.5 移动端优先的交互设计
- 下拉面板三段停靠（收起/半屏/全屏）+ 拖拽吸附
- 类抖音卡片滑动浏览
- 底部 4-Tab 标签栏 + 安全区适配
- 画布双指缩放 + 触摸/鼠标兼容

## 九、当前状态与下一步

根据 `react-migration-plan.md` 的优先级建议，项目处于 **P0（基础框架）到 P1（共享组件）** 阶段之间。尚未看到实际的 React 项目代码文件（如 `package.json`、`vite.config.ts`、`src/` 目录等），说明迁移可能尚未开始或处于极早期。

建议按以下阶段推进：

1. **P0** — 搭建 Vite + React + TS 空壳，4-Tab 视图切换
2. **P1** — 抽取共享组件（Button、SearchBar、Toast、Icon）
3. **P2** — 实现 SearchView 完整链路（搜索→匹配→选卡片→查节点→进入导航）
4. **P3** — 实现 NavView（D3 双模式 + 下拉面板 + 途径点管理）
5. **P4** — 实现 BrowseView（按途径点浏览 + 卡片滑动）
6. **P5** — 实现 TreeView（树管理 + 搜索过滤）
7. **P6** — 视图联动打磨、动画过渡、移动端适配
